# dorothy-brew

Bitget USDT 무기한선물 자동매매 봇의 골격입니다.
**백테스트 → 페이퍼 트레이딩 → 실전**을 같은 코드 경로로 돌리도록 설계했습니다.

> ⚠️ **먼저 읽어주세요**
> 이 저장소에 들어있는 `ema_cross`는 *동작 확인용 샘플*이지 수익 전략이 아닙니다.
> 합성 데이터 백테스트에서 이미 마이너스가 나옵니다. 그게 정상입니다.
> 이 프로젝트가 제공하는 것은 **전략을 안전하게 실험하고 돌릴 수 있는 틀**이고,
> 돈을 버는 전략은 직접 만들어 넣으셔야 합니다.

## 구조

```
캔들 데이터 ──► 전략 ──► 리스크 관리 ──► 주문 실행 ──► 기록/알림
                (신호)     (수량·차단)      (거래소)      (DB·텔레그램)
```

| 모듈 | 역할 |
|---|---|
| `data/` | 캔들 수집(ccxt·CSV·합성), 지표 계산 (EMA/SMA/ATR/RSI) |
| `analysis/` | 스윙 검출, 각도, 피보나치, ICT 유동성, 엘리엇 파동 |
| `strategy/` | 신호 생성. **수량과 자본은 절대 건드리지 않는다** |
| `risk/` | 포지션 사이징, 일일 손실 한도, 연속 손실 차단, 킬스위치 |
| `execution/` | 주문 실행, 중복 진입 방지, 청산 재시도 |
| `exchange/` | 거래소 추상화 — `PaperExchange`(모의) / `BitgetExchange`(실전) |
| `backtest/` | 과거 재생, 성과 지표, 전략 비교, 워크포워드 검증, 깔때기·제거 실험 진단 |
| `journal/` | SQLite 봇 매매 기록 + 실제 매매일지 분석 (기대값·R·순열검정) |
| `notify/` | 텔레그램 알림 |
| `.claude/skills/` | 매매일지 기록 스킬 (분석 가능한 형태로 기록되게 하는 규칙) |

전략이 수량을 정하지 못하게 막은 것이 핵심 설계입니다.
전략이 직접 사이징을 하면 리스크 한도를 우회할 수 있고, 그게 계좌가 사라지는 경로입니다.

## 안전장치

이 봇이 자동으로 막는 것들:

| 장치 | 동작 |
|---|---|
| **손절 강제** | 손절가 없는 진입은 **거부**합니다. 최대 손실을 모르는 주문은 내지 않습니다 |
| **포지션 사이징** | `수량 = (자본 × 1%) ÷ 손절까지의 거리`. 손절이 멀면 작게, 가까우면 크게 |
| **일일 손실 한도** | 하루 -3% 도달 시 당일 신규 진입 중단 |
| **연속 손실 차단** | 4연패 시 당일 중단, 다음 날 자동 재개 |
| **명목가·레버리지 상한** | 설정 레버리지가 한도를 넘으면 자동으로 깎음 |
| **킬스위치** | `touch KILL` 한 번이면 포지션 정리 후 정지 |
| **거래소 스탑 동시 등록** | 손절을 봇 메모리가 아니라 **거래소에** 겁니다. 봇이 죽어도 손절은 살아 있습니다 |
| **중복 진입 방지** | 같은 캔들 재진입 차단 + `clientOid` 멱등성 |
| **루프 예외 격리** | 예외가 나도 봇이 죽지 않습니다 (포지션 방치가 가장 위험) |
| **주문 수량 제약** | 최소 수량 미달이면 주문하지 않습니다. 수량은 항상 **내림** (올림하면 리스크 초과) |
| **거래소 청산 감지** | 스탑으로 청산돼도 포지션 소멸을 감지해 손실 카운터에 반영합니다 |
| **포지션 카운터 보정** | 매 틱 실제 포지션 수로 덮어씁니다 (카운터가 막혀 봇이 멈추는 사고 방지) |

청산은 **어떤 차단 상태에서도 항상 허용**됩니다. 나가는 문은 잠그지 않습니다.

### 실전 모드에서 안전장치가 실제로 작동하려면

거래소 스탑으로 청산되면 **봇은 주문을 낸 적이 없어 그 사실을 모릅니다.**
그러면 일일 손실 한도와 연속 손실 차단이 영원히 0을 보고 작동하지 않습니다.
페이퍼 모드에서는 봇이 모든 체결을 직접 만들기 때문에 이 문제가 드러나지 않습니다.

그래서 `poll_closed_trades()`가 매 틱 포지션 유무를 비교해 청산을 감지합니다.

**손익은 체결 내역이 아니라 자본 변화에서 뽑습니다.** 체결 파싱은 부분체결·수수료·
펀딩비 때문에 틀리기 쉽고 거래소마다 형식이 다릅니다. 자본은 숫자 하나뿐이라 항상 맞습니다.
안전장치를 취약한 경로에 걸어두면 안 되기 때문입니다.

같은 이유로 일일 손실 한도는 **두 가지로 재고 더 나쁜 쪽**을 택합니다:

| 방식 | 정확도 | 신뢰성 |
|---|---|---|
| 기록된 실현손익 | 정확 | 청산이 기록되었을 때만 |
| **자본 낙폭** | 근사 | **항상** — 거래소가 준 숫자 하나 |

청산 감지가 어긋나도 두 번째는 살아 있습니다.

## 사용법

### 1. 실제 데이터로 백테스트

```bash
pip install -r requirements.txt

# 과거 캔들 수집 (API 키 불필요)
python -m dorothy fetch --days 365 --symbol "BTC/USDT:USDT" --timeframe 15m --out data/btc_15m.csv

# 백테스트
cp config/config.example.yaml config/config.yaml
python -m dorothy backtest --csv data/btc_15m.csv --config config/config.yaml
```

결과 읽는 법:

- **PF(손익비) < 1.0** → 손해 보는 전략. 파라미터 만지기 전에 아이디어를 의심하세요
- **거래 30건 미만** → 통계적으로 무의미합니다. 기간을 늘리세요
- **MDD** → "실제로 이 낙폭을 견디고 봇을 안 끌 수 있나?"를 자문하세요. 대부분 못 견딥니다
- 파라미터를 계속 바꿔 수익률을 올리는 건 **과최적화**입니다. 최근 구간을 떼어놓고(out-of-sample) 검증하세요

### 2. 페이퍼 트레이딩

```bash
# 실시간 시세 + 가상 주문 (실제 주문 없음)
python -m dorothy paper --config config/config.yaml

# 네트워크 없이 저장된 캔들 재생
python -m dorothy paper --offline --csv data/btc_15m.csv --config config/config.yaml
```

최소 2주는 돌려보세요. 백테스트에서 안 보이던 문제(체결 지연, 데이터 끊김, 예외)가 여기서 나옵니다.

### 3. 실전

```bash
cp .env.example .env    # 여기에 API 키 입력
python -m dorothy live --config config/config.yaml --sandbox   # 먼저 데모 계정
python -m dorothy live --config config/config.yaml --yes-i-understand-the-risk
```

`--yes-i-understand-the-risk` 없이는 실행되지 않습니다. 의도적입니다.

### 4. 기록 확인

```bash
python -m dorothy status --limit 30
```

## 자기 전략 넣기

`src/dorothy/strategy/` 에 파일 하나 추가하면 됩니다.

```python
from ..models import Action, Candle, Position, Signal
from .base import Strategy, register

@register
class MyStrategy(Strategy):
    name = "my_strategy"

    @property
    def warmup(self) -> int:
        return 100          # 필요한 최소 캔들 수

    def generate(self, candles: list[Candle], position: Position | None) -> Signal:
        if position is None and 조건:
            return Signal(Action.ENTER_LONG, "사유", stop_loss=손절가, take_profit=익절가)
        return Signal(Action.HOLD)
```

`config.yaml`의 `strategy.name`을 바꾸면 끝입니다.

지켜야 할 규칙 두 가지:

1. **수량·레버리지를 계산하지 마세요.** 리스크 매니저 몫입니다
2. **`candles[-1]`은 완결된 봉입니다.** 진행 중인 봉으로 판단하면 신호가 켜졌다 꺼지는 리페인팅이 생깁니다

## ICT 유동성 합류 전략 (`ict_confluence`)

"캔들 각도 + 피보나치 + 엘리엇 파동 + ICT 유동성"을 한 전략에 넣은 것입니다.
네 요소는 **기계화 난이도가 서로 다르고**, 그 차이를 숨기지 않고 구현했습니다.

| 요소 | 코드로 옮겨지는가 | 이 저장소에서의 취급 |
|---|---|---|
| **ICT 유동성** | ✅ 정의가 명확 | 핵심 축. 스윕·FVG·시장구조 전부 하드 조건 |
| **피보나치** | ✅ 계산이 확정적 | 진입 구간(OTE 0.62~0.79). 스윙 정의에만 의존 |
| **각도** | ⚠️ 정규화 필요 | ATR 정규화 후 사용. 아래 설명 참고 |
| **엘리엇 파동** | ❌ 리페인팅 | **감점 전용 소프트 필터**로만 사용 |

### 시나리오 (롱 기준)

```
1. 저점 아래 유동성을 쓸어간다          ← 스윕 (손절 털기)
2. 곧바로 직전 스윙을 종가로 돌파한다     ← CHoCH / BOS
3. 그 구간의 각도가 충분히 가파르다       ← 변위(displacement) 검증
4. 되돌림이 OTE 구간이나 FVG로 들어온다   ← 진입
5. 손절은 스윕 극단 바깥 + ATR 버퍼       ← 같은 자리 재털림 방지
6. 목표는 반대편 유동성 풀               ← 가격이 가려는 곳
```

각 단계가 점수를 내고 **합계가 기준을 넘어야** 진입합니다(합류 점수제).
요소를 끄고 켜며 기여도를 측정할 수 있게 하려는 구조입니다.

### 각도에 대해 — 중요한 함정

**차트에서 눈으로 보는 각도는 그 자체로 의미가 없습니다.**
세로축을 늘리면 45도가 70도가 되고, 창을 넓히면 20도가 됩니다.
BTC의 1,000달러 움직임과 XRP의 0.01달러 움직임을 같은 각도로 비교할 수도 없습니다.

그래서 **ATR 정규화 각도**를 씁니다:

> **1봉당 1 ATR만큼 움직이면 45도**

이렇게 정의하면 종목·타임프레임·가격대가 달라도 같은 숫자를 비교할 수 있습니다.
ICT에서 말하는 displacement(변위)를 수치화한 것이라고 보시면 됩니다.

### 엘리엇 파동에 대해 — 측정한 결과

파동 카운트는 **새 캔들이 오면 과거 카운트가 바뀝니다(리페인팅)**.
"3파였는데 알고 보니 1파였다"가 사후에 성립하는 건 서사로는 괜찮지만,
자동매매에서는 백테스트만 잘 나오고 실전은 안 되는 전형적 원인입니다.

그래서 이 저장소는 리페인팅을 **숨기지 않고 측정합니다**:

```bash
python -m dorothy repaint --csv data/btc_15m.csv
```

```
  카운트가 바뀐 횟수           347  (36.5%)
  방향 자체가 뒤집힘           117  (12.3%)
```

(합성 데이터 기준. 실제 데이터로 직접 재보세요.)

봉의 1/3에서 카운트가 바뀌고 1/8에서 방향까지 뒤집힙니다.
이 숫자를 근거로 엘리엇은 **하드 필터에서 제외**했습니다.
"5파 말미로 보이면 감점" 정도로만 쓰고, "3파니까 진입"은 하지 않습니다.
`elliott_enabled: false`로 아예 끌 수도 있습니다.

### 합류 전략의 고유한 함정 — 그리고 그걸 잡는 도구

필터를 겹겹이 쌓으면 어느 순간 **거래가 0건**이 됩니다.
그런데 백테스트 결과만 보면 "수익률 0%"라서, 전략이 신중한 것인지
조건 하나가 영원히 거짓인지 구분이 안 됩니다.

실제로 이 전략도 처음 만들었을 때 4,000봉에서 거래 0건이었고,
그 원인은 **버그 두 개**였습니다. 진단 도구를 만들어서 찾았습니다.

**1. 깔때기 분석 — 어디서 걸러지는가**

```bash
python -m dorothy diagnose --csv data/btc_15m.csv --strategy ict_confluence
```

```
    1,081 ( 54.9%) █████████████████████ 스윕 후 구조 전환 없음
      422 ( 21.4%) ████████             변위 부족
      312 ( 15.9%) ██████               최근 스윕 없음
      117 (  5.9%) ██                   손익비 부족
```

1순위 항목이 90%를 넘는다면 그 조건은 신중한 게 아니라 고장 난 것입니다.

**2. 제거 실험 — 각 요소가 실제로 기여하는가**

```bash
python -m dorothy ablate --csv data/btc_15m.csv --strategy ict_confluence
```

```
  구성                         거래         순손익      PF     MDD
  전체 (기준선)                    3       -5.41    0.38    1.1%
  − 각도(변위) 필터                22      -14.08    0.68    3.4%
  − 피보나치 OTE                  3       -5.41    0.38    1.1%
  − 엘리엇 필터                    3       -5.41    0.38    1.1%
```

**요소를 껐는데 결과가 같거나 좋아졌다면 그 요소는 없어도 됩니다.**
네 요소를 쌓아 수익이 났을 때, 넷 다 필요해서인지 사실은 하나만 일하고
셋은 파라미터만 늘린 것인지 반드시 확인하세요. 후자라면 그 셋은 과최적화 재료입니다.

## 어떤 전략이 좋은가 — 답을 내는 방법

이 질문에는 보편적인 정답이 없습니다. 대신 **답을 낼 수 있는 절차**는 있습니다.
이 저장소는 그 절차를 도구로 만들어 뒀습니다.

### 먼저, 대부분의 백테스트가 빠뜨리는 것

> **"내 전략이 +18% 났다"는 그 자체로 아무것도 증명하지 않습니다.**

비교 대상이 없기 때문입니다. 반드시 두 기준선과 함께 봐야 합니다:

| 기준선 | 의미 | 못 이기면 |
|---|---|---|
| **매수 후 보유** | 아무것도 안 하고 들고만 있었을 때 | 매매하지 않는 편이 나았다는 뜻 |
| **무작위 진입** | 같은 손절·목표·사이징으로 동전을 던졌을 때 | 그 '분석'은 기여가 0이라는 뜻 |

무작위 대조군이 특히 중요합니다. **ATR 손절 + 3:1 손익비 + 포지션 사이징 조합만으로도
백테스트 성과는 꽤 나옵니다.** 손실을 자르고 이익을 늘리는 규칙 자체에 통계적 성질이
있기 때문입니다. 그 성질을 "내 분석의 성과"로 착각하는 것이 가장 흔한 자기기만입니다.

그래서 모든 전략이 **같은 손절·목표 로직**(`strategy/common.py`)을 공유하도록 만들었습니다.
전략 간 차이가 **진입 시점 하나**로 좁혀져야 비교가 의미를 갖습니다.

```bash
python -m dorothy compare --csv data/btc_15m.csv
```

```
  전략                          거래       수익률     PF      승률     MDD
  donchian                   345    18.94%   1.14   45.8%    9.8%
  ict_confluence               4    -0.94%   0.26   50.0%    1.4%
▷ 매수 후 보유                      1    -9.74%   0.00    0.0%   40.2%
  ema_cross                   84   -10.74%   0.70   36.9%   14.4%
▷ 무작위 진입 (대조군)               111   -16.81%   0.64   36.0%   23.0%
```

### 그다음, 그 수익률이 진짜인지 확인

`compare`에서 1등이어도 아직 아무것도 아닙니다. 파라미터를 그 구간에 맞게 고른 순간,
그 구간에서 잘 나오는 건 당연합니다. **시험 문제를 보고 답을 외운 뒤 같은 시험을 치는 것**과 같습니다.

워크포워드가 이걸 분리합니다:

```
[── 학습 구간 ──][─ 검증 ─]
          [── 학습 구간 ──][─ 검증 ─]
                    [── 학습 구간 ──][─ 검증 ─]
```

학습 구간에서만 파라미터를 고르고, **한 번도 보지 않은** 구간에서 성과를 잽니다.

```bash
python -m dorothy walkforward --csv data/btc_15m.csv --strategy donchian
```

**실제로 돌려본 결과입니다** (합성 데이터 기준 — 수익률 숫자 자체에는 의미가 없고,
학습 대비 검증이 무너지는 *패턴*을 보시면 됩니다):

```
  구간           학습 수익       검증 수익     검증 거래  최적 파라미터
  #0          22.01%      -2.25%        40  atr_stop_mult=2.5, channel=40
  #1           6.95%       2.23%        44  atr_stop_mult=2.5, channel=40
  #2          -7.33%      -2.60%        41  atr_stop_mult=1.5, channel=40
  #3          25.24%      -2.93%        39  atr_stop_mult=2.5, channel=40
──────────────────────────────────────────────────────────
  평균 학습 수익      11.72%
  평균 검증 수익      -1.39%   ← 실전에 가장 가까운 추정치
  효율                -0.12    (검증 ÷ 학습)

  ✗ 학습에선 벌고 검증에선 잃습니다. 전형적인 과최적화입니다.
```

**단일 백테스트에서 +18.94%로 1등이던 전략이, 검증 구간에서는 -1.39%였습니다.**
그 +18.94%는 실력이 아니라 과최적화였습니다.
(같은 도구를 데이터 길이만 바꿔 다시 돌리면 효율 0.24가 나오기도 합니다 —
구간을 조금만 바꿔도 결과가 흔들린다는 것 자체가 신호입니다.)

핵심 지표는 **효율 = 검증 성과 ÷ 학습 성과**입니다:

| 효율 | 해석 |
|---|---|
| 1.0 근처 | 학습 성과가 재현된다. 신뢰할 만하다 |
| 0.5 미만 | 절반이 사라졌다. 과최적화 의심 |
| 0 이하 | 학습에선 벌고 검증에선 잃는다. **파라미터를 더 만지지 말 것** |

### 마지막으로, 어떤 요소가 실제로 일하는지

```bash
python -m dorothy ablate --csv data/btc_15m.csv --strategy ict_confluence
```

요소를 하나씩 꺼봅니다. **껐는데 결과가 같거나 좋아졌다면 그 요소는 없어도 됩니다.**

### 권장 순서

```bash
python -m dorothy fetch --days 730 --timeframe 15m --out data/btc_15m.csv
python -m dorothy compare     --csv data/btc_15m.csv          # 1. 기준선 대비 줄 세우기
python -m dorothy walkforward --csv data/btc_15m.csv --strategy <1등>   # 2. 진짜인지 검증
python -m dorothy ablate      --csv data/btc_15m.csv --strategy <1등>   # 3. 군살 제거
```

2단계에서 효율이 0 이하로 나오면 **그 전략은 버리고 다음 후보로 갑니다.**
파라미터를 더 조정하는 것은 상황을 악화시킬 뿐입니다.

### 포함된 전략

| 전략 | 계열 | 파라미터 수 | 성격 |
|---|---|---|---|
| `donchian` | 추세추종 | 적음 (2) | 가장 오래 검증된 계열. 과최적화 여지가 적음 |
| `ema_cross` | 추세추종 | 보통 (5) | 교과서적. 횡보장에서 계속 털림 |
| `mean_reversion` | 평균회귀 | 보통 (4) | 횡보장에서 벌고 추세장에서 크게 잃음 |
| `ict_confluence` | 시장 미시구조 | 많음 (20+) | 표현력은 높지만 과최적화 위험도 높음 |
| `supertrend` | 추세추종 | 적음 (2) | ATR 추적선. **전환이 드물어 수수료 부담이 낮음** |
| `tma_band` | 평균회귀 | 보통 (3) | TMA 밴드. 기본은 인과적 — 아래 함정 참고 |
| `random` | **대조군** | — | 이걸 못 이기면 분석이 기여를 못 한 것 |

추세추종과 평균회귀를 **둘 다** 넣은 이유가 있습니다. 두 계열은 정반대 성격이라,
어느 쪽이 이기는지가 곧 **그 시장·그 타임프레임의 성질**을 말해줍니다.
둘 다 안 되면 그 구간에는 착취할 시간 편향 자체가 없다는 뜻입니다.

### 파라미터 수에 대해

위 표에서 **파라미터 수를 일부러 표시했습니다.** 파라미터는 많을수록 나쁩니다.
하나 늘 때마다 학습 구간에 우연히 맞출 여지가 곱절로 늘어납니다.

`ict_confluence`가 파라미터 20개가 넘는다는 건 표현력이 높다는 뜻이면서
**동시에 과최적화하기 가장 쉽다는 뜻**입니다. 워크포워드를 반드시 통과시키세요.
격자 탐색(`DEFAULT_GRIDS`)을 일부러 작게 잡아둔 것도 같은 이유입니다.

## 펀딩비 — 방향 편향이 있는 전략일수록 비쌉니다

무기한 선물은 8시간마다 펀딩비가 오갑니다. **롱이 내고 숏이 받습니다**(펀딩률이 양수일 때).

같은 전략에서 `allow_short`만 바꿔 재본 결과입니다 ($100, 167일):

| 펀딩률(8h) | 롱/숏 양방향 | 롱 전용 |
|---|---|---|
| 미반영 | 24.23% | 13.07% |
| 0.01% (평상시) | 24.34% | 12.08% (**-0.99%p**) |
| 0.03% (추세장) | 24.28% | 10.43% (**-2.64%p**) |
| 0.10% (과열) | 24.02% | 3.90% (**-9.18%p**) |

**롱 전용은 과열 구간에서 수익의 70%가 펀딩비로 날아갑니다.**
양방향은 롱이 내고 숏이 받아 대체로 상쇄됩니다.

상승장에서 "롱만 치겠다"는 선택은 방향 판단의 문제만이 아닙니다 —
그때가 바로 펀딩률이 가장 비싼 시기입니다.

## 펀딩률을 신호로 — 가격이 아닌 데이터

지금까지의 분석은 전부 캔들에서 나왔습니다. 펀딩률은 다릅니다.
**포지션이 어느 쪽으로 쏠렸는지를 직접 보여주는 숫자**입니다.

- 펀딩률이 크게 양수 = 롱이 숏에게 돈을 낸다 = 롱 쏠림 → 숏
- 펀딩률이 크게 음수 = 숏이 롱에게 돈을 낸다 = 숏 쏠림 → 롱

절대값이 아니라 **자기 과거 대비(z-score)**로 판단합니다 —
"0.05%면 높다"는 종목·시기마다 다르기 때문입니다.

```bash
python -m dorothy fetch-funding --days 365 --out data/funding.csv
```

```yaml
strategy:
  name: funding_bias
  params:
    funding_csv: data/funding.csv
    entry_z: 2.0        # 2 표준편차를 넘으면 이례적
    exit_z: 0.5         # 정상 범위로 돌아오면 청산
    lookback: 90        # 90회 ≈ 30일
```

### 이 전략에는 구조적 성질이 하나 있습니다

펀딩이 높을 때 숏, 낮을 때 롱을 잡으므로 **항상 펀딩을 받는 쪽에 섭니다.**
합성 데이터 검증에서 실제로 그랬습니다:

```
펀딩 지불 0.00 · 수령 16.98
순손익 48.10 중 약 35%가 펀딩 수입
```

한 번도 펀딩을 내지 않았습니다. 우연이 아니라 설계의 결과입니다.

**그런데 공짜 점심은 아닙니다.** 현실에서 펀딩을 받는 쪽은 '쏠림의 반대편'이고,
가격은 종종 그쪽으로 밀립니다 — 그 위험을 감수한 대가로 펀딩을 받는 겁니다.
합성 데이터는 펀딩과 가격의 그 관계를 전혀 모형화하지 않으므로,
거기서 나온 **가격 손익은 신뢰할 수 없습니다.**

### 백테스트도 실제 펀딩률을 씁니다

기존에는 고정값(0.01%)으로 근사했습니다. 이제 `funding.csv`를 넘기면
**과거 실제 펀딩률**로 비용을 계산합니다. 추세장에서 0.1%까지 치솟는
구간이 반영되므로 훨씬 정직한 숫자가 나옵니다.

## 시간대·세션 분석 — 그리고 그 함정

암호화폐는 24시간 거래되지만 거래량은 전통 시장 시간을 따라갑니다.
아시아·런던·뉴욕 세션, ICT 킬존, 요일 편향을 분해할 수 있습니다.

```bash
python -m dorothy session --csv data/btc_1h.csv --config config/config.yaml
```

### ⚠ 이 분석에는 고유한 함정이 있습니다

**24개 시간대를 재보면 그중 최고는 반드시 좋아 보입니다.**
성과가 완전히 무작위여도 가장 좋은 시간대는 존재합니다.

실제로 이 저장소의 합성 데이터로 돌린 결과입니다:

```
08시   거래 12  승률 83.3%   1회기대 +1.63
11시   거래 10  승률 20.0%   1회기대 -1.07
```

압도적인 차이로 보입니다. **그런데 이 합성 데이터 생성기는 '시각'을 모릅니다.**
봉 인덱스 기반 사인파만 쓰므로 진짜 시간대 편향은 **0**입니다.
원본 시세를 직접 확인해도 시간대 간 평균 수익률 차이는 0.02%p 수준입니다.

즉 저 83% vs 20%는 **24번 뽑기에서 최고와 최저를 고른 결과**일 뿐입니다.

### 그래서 최댓값을 검정합니다

```
최고 구간이 우연일 확률  p=0.082  → 판단 보류
⚠ 어떤 분해도 통계적으로 유의하지 않습니다.
   지금 데이터로는 시간대 편향을 주장할 수 없습니다.
```

개별 구간이 아니라 **'가장 좋은 구간'**을 검정하므로 뽑기 횟수가 자동으로
반영됩니다. 그게 다중검정 보정입니다. 검증도 해뒀습니다:

| 상황 | p값 | 판정 |
|---|---|---|
| 무작위 성과, 24구간 | 0.669 | 우연으로도 흔함 ✓ |
| 13시에 진짜 편향 | 0.000 | 유의미함 ✓ |
| 구간이 많을수록 | p 증가 | 뽑기 횟수 반영 ✓ |

### 근거가 있을 때만 필터를 겁니다

```yaml
strategy:
  name: session_filter
  params:
    base: donchian
    base_params: {channel: 40, exit_channel: 20}
    sessions: ["overlap"]              # 런던·뉴욕 겹침만
    # killzones: ["new_york_open"]     # ICT 킬존
    # skip_weekend: true
```

**리포트의 p값이 0.05 미만일 때만 시간대를 제한할 근거가 있습니다.**
그 전에 거는 필터는 파라미터 하나가 더 느는 것뿐입니다.

## 국면 분석 — "어떤 지표"가 아니라 "지금 어떤 시장인가"

지금까지의 전략은 전부 **항상 매매**합니다. 추세추종은 횡보장에서 계속 털리고
평균회귀는 추세장에서 크게 잃는데, 둘 다 그 사실을 모른 채 신호를 냅니다.

국면 분석은 다른 질문을 던집니다: **지금 이 시장이 내 전략에 맞는가?**

### 분산비(Variance Ratio)로 판별합니다

```
VR = Var(k봉 수익률) / (k × Var(1봉 수익률))

VR > 1  같은 방향이 이어진다 → 추세장
VR ≈ 1  랜덤워크 → 착취할 편향 없음
VR < 1  되돌린다 → 회귀/횡보장
```

자기상관 계수를 아는 인공 시계열로 검증했습니다:

| 시계열 | VR | 판정 |
|---|---|---|
| 강한 추세 (φ=+0.6) | 2.24 | 추세 |
| 약한 추세 (φ=+0.3) | 1.60 | 추세 |
| 랜덤워크 (φ=0) | 1.02 | 무작위 |
| 약한 회귀 (φ=-0.3) | 0.58 | 회귀 |
| 강한 회귀 (φ=-0.6) | 0.38 | 회귀 |

계수를 따라 단조롭게 움직입니다. 지표가 실제로 작동한다는 뜻입니다.

### 1단계 — 내 전략이 어디서 버는지 분해

```bash
python -m dorothy regime --csv data/btc_1h.csv --config config/config.yaml
```

각 매매를 **진입 시점의 국면**으로 분류해 성과를 나눕니다.
한쪽 국면에서만 벌고 있다면, 답은 전략 교체가 아니라 국면 필터입니다.

### 2단계 — 안 맞는 국면에서 쉰다

```yaml
strategy:
  name: regime_filter
  params:
    base: donchian
    base_params: {channel: 40, exit_channel: 20}
    block_volatility: ["low"]        # 저변동 구간 제외
    # allow_trendiness: ["trending"] # 추세장만
```

실측 결과 ($200, 1시간봉):

| 구성 | 거래 | 수익률 | PF | MDD |
|---|---|---|---|---|
| 돈치안 단독 | 181 | 25.20% | 1.37 | 5.8% |
| **+ 저변동 제외** | 153 | 25.07% | **1.45** | **5.1%** |
| + 추세장만 | 22 | 9.34% | **3.04** | **1.9%** |

**저변동만 제외해도 수익률은 유지되면서 PF와 MDD가 개선됩니다.**
추세장만 고르면 PF가 3.04까지 오릅니다 — 돈치안이 추세장 전용 전략이라는
전제가 데이터로 확인되는 셈입니다(대신 거래가 22건으로 줄어듭니다).

`mtf_filter`와 마찬가지로 **청산 신호는 막지 않습니다.**
국면이 나빠도 나가는 문은 열려 있어야 합니다.

## 거래 빈도가 성과를 결정합니다

$100 백테스트에서 가장 눈에 띈 숫자는 수익률이 아니라 **수수료**였습니다.

```
순손익 $13.20  ·  지불 수수료 $26.33   ← 총이익의 2/3
```

그래서 "빈도를 줄이면 나아지는가"를 실측했습니다. 전략은 그대로 두고
돈치안 채널 길이만 바꿔 거래 횟수를 조절한 결과입니다 ($100, 125일):

| 채널 | 거래 | 총이익 | 수수료 | 순손익 | 수수료/총이익 | PF |
|---|---|---|---|---|---|---|
| 10 | 875 | 15.60 | 48.64 | **-33.04** | 312% | 0.86 |
| 20 | 705 | 56.86 | 51.94 | +4.92 | 91% | 1.02 |
| 40 | 547 | 99.72 | 47.61 | +52.11 | 48% | 1.22 |
| 80 | 433 | 108.75 | 39.13 | **+69.62** | 36% | 1.36 |
| 160 | 353 | 92.97 | 31.54 | +61.43 | 34% | 1.40 |

**전략을 바꾼 게 아니라 빈도만 낮췄는데 PF가 0.86 → 1.40이 됐습니다.**

소액 계좌에서 새 전략을 검토하실 때 첫 질문은 "얼마나 정확한가"가 아니라
**"얼마나 자주 매매하는가"**여야 합니다.

## 리페인팅 지표를 거르는 법

시중 지표·EA 중 상당수는 **중심이동(centered) 평균**을 씁니다. MT4/MT5의
'TMA 밴드'가 대표적입니다. 중심이동은 i 시점 값을 계산할 때 i 이후 캔들을 씁니다.
차트에서는 가격을 기가 막히게 감싸는 것처럼 보이고 백테스트도 훌륭하게 나오지만,
**실시간에는 그 값을 알 수 없습니다.**

같은 규칙·같은 데이터에서 지표 계산 방식만 바꿔 실측한 결과입니다:

```bash
PYTHONPATH=src python3 scripts/lookahead_demo.py
```

```
인과적 TMA (정상)          거래  90  승률  55.6%  최종 $ 47.57  (-52.43%)
중심이동 TMA (미래 참조)     거래 168  승률 100.0%  최종 $707.97  (+607.97%)
```

**승률 100%는 전략이 훌륭하다는 뜻이 아니라 미래를 봤다는 뜻입니다.**

지표나 EA를 검토하실 때 던질 질문:

1. 확정된 과거 봉의 지표값이 나중에 바뀌는가? (바뀌면 그 백테스트는 무의미)
2. 판매자 백테스트의 승률이 비정상적으로 높지 않은가?
3. 아웃오브샘플(학습에 안 쓴 구간) 성과를 제시하는가?

### "미래참조로 만들어달라"가 불가능한 이유

중심이동 TMA는 i 시점 값을 계산하려면 **i+10봉의 미래**가 필요합니다.
실시간에는 그 미래가 아직 없으므로 현재 봉 값이 항상 `None`입니다.

```
100봉 시점의 마지막 12개: 값 값 None None None None None None None None None None
```

코드가 막는 게 아니라 **계산이 불가능한 것**입니다. 실제 봇 경로로
2,921봉을 돌려도 진입 신호는 0건입니다.

### 대신 쓸 수 있는 것 — `delayed` 모드

중심이동 선의 **현재 봉** 값은 없지만, **10봉 전 값은 이미 확정**돼 있습니다.
그걸 기준선으로 쓰면 중심이동의 매끄러움을 얻으면서 미래참조는 하지 않습니다.
대가는 10봉만큼의 지연입니다 — 공짜는 없고, 이게 정직한 가격표입니다.

| mode | 설명 | 실거래 | 합성 데이터 결과 |
|---|---|---|---|
| `causal` | 일반 TMA (기본값) | ✅ | 264거래 · -36.79% · PF 0.42 |
| `delayed` | 중심이동 + 10봉 지연 | ✅ | 319거래 · -31.29% · PF 0.52 |
| `centered` | 중심이동 현재 봉 | ❌ | **0거래** — 값이 존재하지 않음 |

```yaml
strategy:
  name: tma_band
  params:
    mode: delayed      # causal | delayed | centered
```

## 소액으로 시작할 때 — 최소 주문 수량

**"$10으로 얼마까지 되나"의 실제 답은 "주문이 거의 안 나간다"입니다.**

거래소에는 최소 주문 수량이 있습니다(Bitget BTCUSDT 무기한 = 0.0001 BTC).
자본이 작으면 `(자본 × 1%) ÷ 손절폭`으로 계산한 수량이 그 아래로 떨어집니다.

같은 데이터·같은 전략을 자본만 바꿔 돌린 결과입니다:

| 시작 자본 | 종료 | 수익률 | 거래 |
|---|---|---|---|
| $10 | $10.02 | +0.20% | **3건** |
| $50 | $54.90 | +9.79% | 338건 |
| $100 | $109.73 | +9.73% | 338건 |
| $1,000 | $1,100.90 | +10.09% | 338건 |

**제약을 반영하기 전에는 $10도 338건에 +10.14%로 나왔습니다.** 실제로는 나가지도
못할 주문을 백테스트가 체결시키고 있었던 겁니다. 소액 계좌 결과가 통째로 거짓말이었습니다.

실전 최소선은 대략 **$50~100**입니다. 그 아래에서는:

- 대부분의 신호가 수량 미달로 거부됩니다
- 레버리지를 올려 수량을 맞추려 하면 수수료 부담이 그만큼 커집니다
  (자본 대비 왕복비용은 레버리지에 비례합니다 — 10배면 매매당 2.2%)

live 모드에서는 설정값 대신 **거래소가 알려주는 실제 제약**을 읽어 씁니다.
자본 대비 최소 주문이 너무 크면 시작할 때 경고합니다.

## 매매일지 분석 — 내 실제 우위 찾기

백테스트는 "이 규칙이 과거에 통했나"를 묻습니다.
매매일지 분석은 **"내가 실제로 뭘 잘하고 뭘 못하나"**를 묻습니다.

후자가 먼저입니다. **이미 갖고 있는 우위를 자동화하는 편이,
없는 우위를 새로 만드는 것보다 훨씬 확률이 높습니다.**

```bash
# 노션 매매 기록 → ··· → 내보내기 → CSV
python -m dorothy journal data/내매매일지.csv

# 샘플로 먼저 보기
python -m dorothy journal examples/journal_sample.csv
```

### 나오는 것

| 분석 | 답하는 질문 |
|---|---|
| 방향/레버리지/태그/요일별 기대값 | 어떤 조건에서 벌고 잃나 |
| **순열검정 p값** | 그 차이가 우연일 확률은 얼마인가 |
| R 분석 | 계좌 크기와 무관한 진짜 실력은 얼마인가 |
| 집중도 | 한 방에 의존하고 있나 |
| 사이징 변동계수 | 베팅 크기가 일정한가 |
| 위험 신호 | 나쁜 습관이 보상받고 있나 |

### 왜 p값을 같이 내놓는가

20~30건짜리 기록에서 **"숏이 롱보다 낫다" 같은 결론은 대부분 우연입니다.**
그래서 그룹 비교마다 순열검정으로 "이 차이가 순전히 운일 확률"을 함께 냅니다.

```
  방향         숏 vs 롱          p=0.215  → 우연으로도 흔함
  규율         계획대로 vs 규율 위반   p=0.000  → 유의미함
```

라벨을 무작위로 섞어 다시 나눴을 때 실제만큼 큰 차이가 얼마나 자주 나오는지 세는 방식입니다.
표본이 작아 정규성을 가정할 수 없을 때 쓰는 가장 단순하고 정직한 방법입니다.

**p가 크게 나오는 것은 "차이가 없다"가 아니라 "아직 결론을 낼 수 없다"는 뜻입니다.**

### 가장 중요한 경고: 보상받는 나쁜 습관

```
  ⚠ 나쁜 습관이 보상받고 있습니다: 과도한 레버리지(+105)
     지금 수익이 난다는 사실은 그 습관이 옳다는 증거가 아닙니다.
     보상받은 습관은 강화되고, 표본이 쌓이면 한 번에 청산됩니다.
```

부정적 태그(뇌동매매·과도한 레버리지·손절 늦음 등)가 붙은 매매가 **돈을 벌고 있을 때**
띄우는 경고입니다. 이게 이 리포트에서 가장 위험한 항목입니다.
운 좋은 구간에서 강화된 습관은 반드시 청구서가 돌아옵니다.

### R이 왜 중요한가

**R = 손익 ÷ 계획했던 손절액.**

금액 기대값은 베팅 크기가 커지면 같이 커집니다. R은 그렇지 않습니다.
계좌가 100달러든 10,000달러든 "평균 +0.3R"은 같은 의미입니다.
그래서 R이 **실력에 가장 가까운 단위**입니다.

R을 계산하려면 `손절액` 칸이 채워져 있어야 합니다.
비어 있으면 리포트가 그렇게 말하고, 그게 보통 **가장 먼저 고칠 것**입니다.

### 자동화로 넘어가는 조건

기록이 아래 셋을 갖추고 50건쯤 쌓이면, 그때 "내 우위"를 코드로 옮길 수 있습니다.

1. **손절액** — R 분석이 열립니다
2. **진입 근거** — 어떤 셋업이 통하는지 분류됩니다
3. **일정한 증거금 비율** — 매매 간 비교가 가능해집니다

그 전에는 데이터가 질문에 답할 만큼 쌓이지 않은 상태입니다.


### 기록 단계에서 분석 가능하게 만들기

분석은 기록의 품질을 넘지 못합니다. `.claude/skills/bitget-trade-journal/SKILL.md`는
비트겟 스크린샷을 노션에 옮기는 스킬이며, **분석에 필요한 칸이 비지 않도록** 되어 있습니다.

바뀐 점:

| 항목 | 전 | 후 |
|---|---|---|
| 손절액 | "모르면 비워둔 채로 진행" | **필수.** 미설정이면 `0` + `손절 미설정` 태그 |
| 진입 근거 | 자유 서술 (거의 안 채워짐) | **`[셋업이름] 설명` 형식.** 선택지로 제시 |
| 질문 방식 | 항목별로 따로 | 한 메시지에, `AskUserQuestion` 선택지로 |
| 손절 준수 | 확인 안 함 | 실제 손실 > 손절액×1.1 이면 `손절 늦음` 자동 태그 |

핵심은 **"모르면 비워둔다"를 "없었으면 없었다고 기록한다"로 바꾼 것**입니다.
빈칸은 정보가 없는 것이고, "손절 미설정"은 그 자체로 중요한 정보입니다.
빈칸은 나중에 복구할 수 없습니다.

`[셋업이름]` 형식이 중요한 이유는 **그게 있어야 셋업별로 묶어 기대값을 낼 수 있기**
때문입니다. 자유 서술만으로는 그룹화가 불가능합니다.

```
  셋업별  (진입 근거에 [셋업] 표기된 비율 100%)
  구분        건수     총손익    1회기대     승률
  유동성스윕      6    110.17    15.1%   100.0%
  지지저항       4     36.82    11.9%    50.0%
  돌파         2    -26.81   -10.0%    50.0%
  감          3    -93.03   -36.2%     0.0%
```

셋업 이름은 목록에서 재사용합니다(`지지저항`/`되돌림`/`돌파`/`유동성스윕`/`이평`/`뉴스`/`감`).
매번 새로 지으면 통계가 쌓이지 않습니다. `감`을 정직하게 고르는 것도 데이터입니다.

## 통과했다고 발표했던 것, 그리고 그게 왜 틀렸나

> **⚠ 철회합니다.** 이 절은 원래 "이 저장소에서 `|t| >= 2`를 넘긴 유일한
> 신호"로 12시간봉 돈치안40 롱을 발표했습니다. **그 t값이 틀렸습니다.**
> 아래는 무엇을 잘못 셌는지와 다시 잰 결과입니다.

### 무엇이 틀렸나 — 겹치는 신호를 독립 표본으로 셌습니다

돌파 신호는 서로 겹칩니다. 40봉 고가를 뚫으면 그 다음 몇 봉도 대개 같이
뚫려 있습니다. 신호마다 "앞으로 60봉"의 결과를 붙여 t를 내면 **같은 가격
움직임을 여러 번 세게 됩니다.**

표본 수는 늘어나지만 정보량은 그대로입니다. t는 √n에 비례하므로 딱 그만큼
부풀려집니다. 그리고 봇은 **한 번에 포지션 하나만** 듭니다
(`max_open_positions: 1`) — 보유 중에 들어온 신호는 애초에 잡을 수 없습니다.
잡을 수 없는 것을 실적에 넣으면 안 됩니다.

```
12시간봉 · 돈치안 채널 40 · 롱 전용 · 왕복 0.56%

겹침 포함   291건   1회 +1.1975%   t = 2.67   ✓ 통과   ← 발표했던 숫자
겹침 제거   115건   1회 +0.7335%   t = 0.99   ✗ 탈락   ← 실제로 잡히는 것

보유 중이라 잡을 수 없었던 신호 176건 (60%)
겹쳐 세면 t가 √(291/115) ≈ 1.59배 부풀려집니다
```

같은 전략, 같은 데이터, 같은 수수료입니다. **세는 방법만 달랐습니다.**

직접 확인할 수 있습니다:

```bash
PYTHONPATH=src python3 -m dorothy.cli edge \
    --config config/donchian12.rejected.yaml --csv data/btc_12h.csv --max-bars 60
```

### 다시 잰 검증표 — 전부 무너집니다

원래 "채널 7개 중 5개 통과, 타임프레임 6개 중 5개 통과, 둘 다 단조 증가하는
고원"이라고 적었습니다. 그게 이 발표의 핵심 근거였습니다. 겹침을 빼고 다시 재면:

```
채널 (12시간봉, 롱 전용)              타임프레임 (채널 40, 롱 전용)
        겹침포함      겹침제거                 겹침포함      겹침제거
 채널    n     t      n     t          봉     n     t      n     t
  10   528  1.23    197  -0.08 ✗       4h   706  1.43    284  1.01 ✗
  15   451  1.39    165   0.91 ✗       6h   507  1.58    207  0.97 ✗
  20   401  1.87    156   0.64 ✗       8h   400  1.83    159  2.03 ✓
  30   323  1.92    131   0.21 ✗      12h   291  2.67 ✓  115  0.99 ✗
  40   291  2.67 ✓  115   0.99 ✗       1d   154  1.46     69  0.41 ✗
  60   235  2.83 ✓   95   1.28 ✗       3d    57  3.61 ✓   23  4.03 ✓
  80   215  2.77 ✓   85   1.35 ✗
        → 7개 중 0개 통과                    → 6개 중 2개 통과
```

**채널은 7개 중 0개가 통과합니다.** t값이 −0.08에서 1.35 사이에 흩어져 있고
단조성도 고원도 없습니다. "고른 값이 좋은 구간 한가운데 있다"던 근거가
통째로 사라집니다.

타임프레임에서 남은 둘도 근거가 못 됩니다. 8h는 t=2.03으로 경계선이고,
3d는 **23건**짜리입니다. 13번 재서 2개가 걸린 것은 우연으로 충분히 설명됩니다
— 이 문서가 다른 전략들을 기각할 때 쓴 것과 같은 잣대입니다.

방향과 기간도 마찬가지입니다.

```
롱 전용   겹침포함 291건 t=2.67 ✓    겹침제거 115건 t=0.99 ✗
롱+숏     겹침포함 456건 t=1.44 ✗    겹침제거 191건 t=0.57 ✗

전반      57건  1회 +1.201%  t=0.94 ✗
후반      58건  1회 +0.274%  t=0.36 ✗
```

원래 "후반 t=1.20이 유일한 우려"라고 적었습니다. 겹침을 빼면 **전반도
통과하지 못합니다.** 약해진 게 문제가 아니라 처음부터 없었습니다.

### 리스크 사이징을 걸고 실제로 돌리면

신호 단위가 아니라 봇이 실제로 체결한 것만 세면 이렇습니다.

```
142건 (평균 22일에 한 번) · 1건당 +0.876% · t = 1.55 ✗
8.6년 +37.31% = 연 +3.73% · MDD 5.9%

1건당 우위의 95% 신뢰구간  [-0.235%, +1.987%]
연으로 환산하면            연 -3.9% ~ +32.6%
```

**신뢰구간이 0을 포함합니다.** 진짜 우위가 0이거나 음수일 가능성을 배제하지
못합니다. 8.6년을 다 써서 이 정도입니다.

### 그러면 겹침을 뺀 t가 2를 넘는 것은 있는가 — 202개를 훑었습니다

철회한 뒤 제대로 찾아봤습니다. **규칙을 재기 전에 정하고 바꾸지 않았습니다.**

```
탐색기간  앞 60% (2018-01 ~ 2023-03)   ← 여기서만 훑는다
검증기간  뒤 40% (2023-03 ~ 2026-08)   ← 후보가 정해진 뒤에만 연다

통과 조건 (셋 다)
  1. 겹침 제거 표본이 탐색기간·검증기간 각각 30건 이상
  2. 탐색기간 순수익 > 0 이고 |t| >= 본페로니 임계값
  3. 검증기간 순수익 > 0 이고 |t| >= 2
```

훑은 것: 돈치안·EMA 교차·슈퍼트렌드·평균회귀·TMA 밴드 × 파라미터 ×
롱전용/롱숏 × 4h·6h·8h·12h·1d, 그리고 손절·익절 배수 16조합,
체제/상위봉/세션 필터. **총 202개** (결과가 같은 것은 하나로 셈).

```
본페로니 임계값 |t| >= 3.80   (보정 안 하면 2.00)

  설정                              탐색기간            검증기간
                                 n    1건당     t     n    1건당     t
  session_filter 8h 주말제외      79   +2.58%  3.18    61   +0.80%  1.22  ✗
  donchian 8h 롱 채널80          69   +2.11%  2.48    53   +0.02%  0.03  ✗
  donchian 8h 롱 채널40          94   +1.86%  2.47    65   +0.70%  1.11  ✗
  mtf_filter 8h 상위봉 추세      80   +1.94%  2.46    60   +0.69%  1.08  ✗
```

"보정 없이 8개 통과"도 함정입니다. 202개를 재면 우위가 전혀 없어도

### 펀딩비 수취 (델타 중립 캐리) — 구조는 만들었고, 데이터가 없습니다

가격을 맞히는 길이 막혀서 **가격을 안 맞히는 구조**를 봤습니다.
현물 BTC를 사고 같은 수량의 무기한선물을 숏 칩니다.

```
총가치 = Q·P(현물) + M(증거금) + (P진입 - P)·Q(선물 미실현)
       = Q·P진입 + M          ← P가 사라진다. 남는 것은 펀딩비뿐이다.
```

**실제 비트겟 펀딩률로 재봤습니다 — 수수료가 다 먹습니다.**

2026-08-18 ~ 08-31, BTCUSDT, 40회 정산:

```
평균 +0.0050%/8h   표준편차 0.0054%   음수 15%   t=5.88
40회 중 13회가 정확히 +0.0100%  ← 상한선

실제로 9일간 돌린 결과 (자본 10,000)
  1배   펀딩 +9.28 / -1.70   수수료 -17.80   →  -0.102%
  2배   펀딩 +12.37 / -2.27  수수료 -23.74   →  -0.136%
  3배   펀딩 +11.45 / -2.35  수수료 -26.72   →  -0.176%
```

펀딩은 확실히 양수입니다(t=5.88). **그런데 왕복 수수료를 덮는 데만
약 21일이 걸립니다.** 오래 들고 있어야 남습니다:

```
보유기간    1배      3배
   13일   -0.06%   -0.09%
   30일   +0.07%   +0.10%
   90일   +0.52%   +0.77%
  365일   +2.58%   +3.87%
```

**연 2.6~3.9%입니다.** 그리고 상한이 0.01%라 천장이 정해져 있습니다 —
계속 상한에 붙어 있어도 3배에서 연 8.2%가 최대입니다.

> ⚠ **13일치 표본입니다.** 이 창이 좋았는지 나빴는지 13일로는 알 수 없습니다.

켜고 끄는 규칙이 필요합니다. 규칙 5개를 만들어 4년 전체에 돌렸습니다.

```

  직전 30일 펀딩 평균 > 0.005%   67%     6.97%    8.74%
  직전 30일 펀딩 평균 > 0.01%    34%     5.99%    7.16%
  가격 > 200일 이동평균          58%     6.57%    6.74%
```

**실행 가능한 최선은 연 7~9%입니다.** 2021년의 15~25%가 아닙니다.

- `가격 > 200일 이평`은 대조군과 사실상 같습니다 (6.57% vs 6.66%).
- 제일 나은 `펀딩 > 0`은 92% 켜져 있습니다 — 국면 판정이라기보다
  **최악의 몇 구간만 피하는 것**입니다. 3배에서 6.10% → 9.00%로 올라가는
  것도 축소 사건 몇 번을 피해서지 강세장을 맞혀서가 아닙니다.
- 규칙을 5개 재서 고른 것이라, 이 차이 자체가 우연일 수 있습니다.

> ⚠ 대조군을 처음엔 잘못 쟀습니다. '항상 켜기'는 2020년 상승장에서 포지션이
> 전량 정리되며 조기 종료돼 4년이 아니라 1년으로 측정됐고, 그래서 규칙들이
> 실제보다 훨씬 좋아 보였습니다(+10.00% vs +29.42%). 재진입을 넣어
> 고쳤습니다.

> 📌 남은 확인: 위 데이터는 **바이낸스 2020~2023**입니다. 비트겟 최근
> 1년치는 `fetch-funding`으로 직접 받아 다시 재야 합니다.

**1. 자본 기준 수익률은 명목가 기준의 L/(L+1)배입니다.**

자본이 현물과 증거금으로 쪼개지기 때문입니다. 이걸 구분 안 하면
"펀딩 연 11%"를 계좌 수익률로 착각합니다.

```
   펀딩률/8h      1배     2배     3배     5배
     0.005%     2.7%    3.7%    4.1%    4.6%
     0.010%     5.5%    7.3%    8.2%    9.1%
     0.020%    11.0%   14.6%   16.4%   18.3%
```

**2. 숏 다리의 청산 위험 — 이건 실측입니다.** (BTC 8.6년 실제 가격)

증거금을 한 푼도 안 채웠을 때 청산되는 상승폭에 실제로 도달한 비율:

```
  레버리지   청산 상승폭   90일 내   365일 내
     1배        100%        7%        46%
     2배         50%       22%        65%
     3배         33%       35%        73%
     5배         20%       50%        83%
```

**1배도 안전하지 않습니다.** 1배면 명목가 = 증거금이라 가격이 2배가 되면
증거금이 정확히 0이 됩니다. 365일 창의 46%에서 그 일이 있었습니다.

**3. 증거금이 모자랄 때 무엇을 하느냐가 생사를 가릅니다.**

만들고 돌려보다 발견한 것입니다.

```
같은 가격 경로(BTC 8.6년), 대응 방식만 다르게

  현물만 팔아 증거금 보충   →  -100%   (헤지가 100% 어긋남)
  양 다리를 같이 축소       →   +8.7%  (청산 없음, 중립 유지)
```

현물을 팔면 숏은 그대로인데 헤지가 줄어 **순숏**이 됩니다. 상승이 이어지면
더 팔아야 하고, 그러다 현물이 바닥납니다. 양 다리를 같이 줄이면
**원리상 청산되지 않습니다** — 포지션이 작아질 뿐입니다.

**4. 수수료를 덮으려면 오래 들고 있어야 합니다.**

```
   7일 보유 → 평균 펀딩률 0.0152%/8h 필요
  30일       → 0.0036%
  90일       → 0.0012%
```

하루 만에 접으면 0.107%/8h가 필요합니다 — 평상시의 10배입니다.
**단타로 할 수 있는 구조가 아닙니다.**

**남은 것: 실제 펀딩률.** 사용자 컴퓨터에서는 받을 수 있습니다.

```bash
PYTHONPATH=src python3 -m dorothy.cli fetch-funding \
    --config config/config.yaml --days 365 --out data/funding.csv

PYTHONPATH=src python3 -m dorothy.cli carry --config config/config.yaml \
    --csv data/btc_1h.csv --funding-csv data/funding.csv --leverage 1,2,3
```

> 📌 이 구조에는 **현물 다리가 필요합니다.** 무기한선물만 쓰면 델타 중립이
> 아니라 그냥 방향성 숏입니다.

### 그래도 직접 매매한다면 — "적당한 배율"이 몇 배인가

우위 있는 신호는 못 찾았지만, **배율을 얼마로 둘지는 정확히 계산할 수 있습니다.**

리스크 사이징을 쓰면 배율은 수량을 바꾸지 않습니다(그건 `risk_per_trade`가
합니다). 배율이 정하는 것은 **청산가**입니다.

```
청산까지의 거리 ≈ 1/배율 − 유지증거금률(0.5%)

  3배 → 32.8%    5배 → 19.5%    10배 → 9.5%    20배 → 4.5%
```

여기에 손절폭을 겹쳐 봅니다. **손절폭이 청산 거리보다 멀면 손절은
영원히 발동하지 않습니다.** 거래소가 먼저 가져가고, 그러면 잃는 것이
계획한 1%가 아니라 그 포지션의 증거금 전부가 됩니다.

BTC 8.6년 실측. 안전 상한은 **상위 1% 손절폭에도 청산이 손절보다 두 배 먼** 배율입니다.

```
              ATR × 1.5                    ATR × 2.0
 타임프레임  중앙값  상위1%   상한      중앙값  상위1%   상한
    1시간   1.06%   4.19%  11.3배     1.42%   5.59%   8.6배
    4시간   2.30%   8.19%   5.9배     3.07%  10.92%   4.5배
   12시간   4.26%  14.48%   3.4배     5.68%  19.31%   2.6배
```

**긴 봉일수록 손절이 멀어져 낮은 배율만 허용됩니다.** 12시간봉에 ATR×2.0으로
10배를 쓰면 12%의 매매에서 손절이 무력해집니다.

### 손절을 좁히면 배율 여유는 늘지만, 대가가 있습니다

모든 봉에서 진입했다고 보고 삼중 장벽으로 잰 1회 순수익 (왕복 0.22% 반영,
체결가는 닿은 장벽 가격):

```
 타임프레임   R:R    ATR×1.5    ATR×2.0
    1시간    1.5    -0.218%    -0.191%
    1시간    2.0    -0.208%    -0.192%
    4시간    1.5    -0.272%    -0.102%
    4시간    2.0    -0.201%    +0.040%
   12시간    1.5    +0.057%    +0.133%
   12시간    2.0    +0.073%    +0.279%
```

**12개 비교 전부 ATR×2.0이 낫습니다.** 다만 방향이 일관된다는 것뿐이고,
**통계적으로 확립된 것은 아닙니다** — 3개 타임프레임이 같은 1시간봉에서
리샘플된 것이라 독립 검정 12개가 아닙니다.

진짜 근거는 통계가 아니라 사이징 식입니다.
`수량 = 리스크 ÷ 손절폭`이라 손절을 좁히면 **수량이 커집니다.**

```
4시간봉 중앙값, 자본 10,000, 1회 리스크 1%

  ATR×1.5  손절폭 2.30%  →  명목가 4,348  왕복 수수료 9.57
  ATR×2.0  손절폭 3.07%  →  명목가 3,257  왕복 수수료 7.17
```

명목가가 33% 크니 수수료도 33% 큽니다. 움직임은 작아지는데 비용은 커집니다.
**손절을 좁혀 얻는 것은 쓸 필요도 없는 배율 여유**(배율은 천장일 뿐 수량을
늘리지 않습니다)**이고, 내주는 것은 실제 수수료입니다.**

이건 백테스트 결과가 아니라 산수라서, 표본이 적어도 성립합니다.

### 익절 배수(R:R)는 이 데이터로 정할 수 없습니다

손절을 2.0으로 고정하고 R:R을 훑었습니다. **겹침을 빼면 전부 탈락합니다.**

```
4시간봉 · 손절 ATR×2.0 · 겹침 제거 후

  R:R   겹침포함 t    표본     1회 순수익      t     판정
  1.0     -2.82      1,211    -0.094%   -0.77    ✗
  1.5     -1.27        871    +0.021%   +0.11    ✗
  2.0     +0.42        648    +0.169%   +0.67    ✗
  2.5     +0.77        528    +0.364%   +1.12    ✗
  3.0     +0.43        459    +0.291%   +0.78    ✗
```

12시간봉도 같습니다 (전부 t < 1.6). 그리고 겹침 포함 순수익은
2.0 → 2.5 → 3.0에서 +0.279% → +0.134% → +0.377%로 **단조롭지 않습니다.**
잡음입니다. 여기서 최대값을 골라 "최적 R:R"이라 부르면 안 됩니다.

**말할 수 있는 것은 R:R 1.0을 피하라는 것뿐입니다** — 유일하게 뚜렷하게
나쁜 쪽이었습니다(겹침 포함 t=-2.82). 그 위로는 취향입니다.

```bash
PYTHONPATH=src python3 -m dorothy.cli liqcheck \
    --config config/trading.yaml --csv data/btc_4h.csv
```

`config/trading.example.yaml`에 반영해뒀습니다 (4시간봉·ATR×2.0·3배,
익절 4.0, 1회 리스크 1%, 고점 대비 낙폭 20% 한도).

### 분할 주문은 이 신호에 안 맞습니다

같은 신호에 분할 진입을 붙여 재봤습니다.

```
방식                  건수   이길때   질때   1회 순수익      t      합계
시장가 전량            291   100%   100%  +1.1983%  2.87  +348.7%  ← 최선(상대)
단일 지정가 0.25 ATR   230   100%   100%  +1.1392%  2.38  +262.0%
분할 3개·깊이 0.25     290    85%    97%  +1.0769%  2.75  +312.3%
분할 5개·깊이 1.0      290    53%    79%  +0.7446%  2.47  +215.9%
분할 8개·깊이 1.5      290    40%    68%  +0.5950%  2.43  +172.5%
```

> ⚠ 위 표의 t값은 **겹침을 포함해 센 것**이라 부풀려져 있습니다(위 절 참고).
> 다만 여기서 보려는 것은 방식 간의 **상대 비교**이고, 다섯 줄 모두 같은
> 방식으로 셌으므로 아래 결론은 그대로입니다.

**깊게 깔수록 단조롭게 나빠집니다.** `이길때` / `질때` 열이 이유입니다 —
깊이 1.5에서 **이길 때 40%, 질 때 68%**가 채워집니다.

돌파 신호에서 되돌림을 기다리는 것은 **논리적으로 상충합니다.** 크게 가는
것(이기는 것)은 안 돌아오니 조금만 잡고, 실패하는 것은 되돌아오니 가득 잡습니다.
수수료 절감(0.09%p)이 이 손해를 덮지 못합니다.

> 분할 주문이 맞는 자리는 **"떨어지면 산다"가 전제인 평균회귀형**입니다.
> 거기서는 되돌림이 곧 신호라 상충이 없습니다.

### 복리는 마법이 아니라 양날입니다

수량이 자본에 비례하므로 이 봇은 복리로 굴러갑니다. 그런데 **손실도 곱셈으로
들어옵니다** — −50%를 맞으면 +100%를 벌어야 본전입니다. 베팅을 키우면 평균
수익은 선형으로 늘지만 변동성 손실은 **제곱으로** 늘어납니다.

그래서 최적점이 있고, 넘으면 되돌아옵니다. 200원으로 시작해 8.6년:

```
1회리스크    최종자본     연환산      MDD
    1%       275원    +3.76%    5.9%
    5%       823원   +17.88%   27.6%
   12%     2,620원   +34.87%   58.6%
   16%     3,328원   +38.67%   73.0%   ← 최고점
   20%     3,126원   +37.67%   83.6%
   25%     1,871원   +29.70%   92.1%
   40%        19원   -24.05%   99.6%
```

**1회 리스크 40%에서는 200원이 19원이 됩니다.** 전략은 여전히 1회당 이기는데도요.

그리고 그 "최적" 16%는 **MDD 73%를 끝까지 버텨야** 나오는 숫자입니다.
게다가 이 8.6년 역사에 맞춰 사후에 고른 값이라 실전에서 그 값이 최적일
보장이 없습니다. 실무에서 켈리 최적값의 **절반 이하**를 쓰는 이유입니다.

### 저빈도 전략에는 일일 한도가 아무것도 막지 못합니다

이 전략은 **평균 22.1일에 한 번** 매매합니다. 그런데 `max_daily_loss_pct`와
`max_consecutive_losses`는 둘 다 **하루 단위로 초기화**됩니다. 손실이 며칠에
걸쳐 나므로 같은 날 두 번 매매하는 일이 거의 없고, 한도가 걸릴 기회 자체가
없습니다.

계측해서 확인했습니다. `halt_reason`을 가로채 세어보니:

```
1회 리스크  1%  →  142거래  차단 0회
1회 리스크 12%  →  142거래  차단 0회
```

**1회 리스크를 12%로 올려도 차단이 한 번도 발동하지 않습니다.**
코드가 고장난 게 아니라, 일일 한도가 일중 매매를 전제로 설계됐기 때문입니다.

> 이게 위험한 이유: 1회 리스크 12%로 돌리는 사람은 "일일 손실 3% 한도가
> 나를 지킨다"고 믿지만, 실제로는 아무것도 막아주지 않습니다.

그래서 **고점 대비 낙폭 한도**(`max_drawdown_pct`)를 넣었습니다. 날짜와
무관하게 걸리므로 매매 빈도에 상관없이 작동합니다.

```
1회리스크  낙폭한도   거래      수익률    연환산     MDD   수익/MDD
   1%       끔     142   +37.31%   +3.76%   5.9%     6.29
   1%      20%     142   +37.31%   +3.76%   5.9%     6.29   ← 과잉 차단 없음
   5%      20%      75  +106.10%   +8.77%  24.3%     4.37
  12%       끔     142 +1210.03%  +34.87%  58.6%    20.64
  12%      20%       4   -20.84%   -2.68%  23.2%    -0.90   ← 즉시 정지
```

마지막 두 줄이 핵심입니다. **+1210%는 58.6% 낙폭을 끝까지 버텨야 나오는
숫자입니다.** 낙폭을 20%로 묶으면 4거래 만에 멈추고 마이너스로 끝납니다.
높은 리스크는 그만큼의 낙폭을 감당할 때만 성립합니다.

기본값은 `0.0`(끔)입니다. 켜는 것은 선택이지만,
`config/donchian12.example.yaml`에는 `0.20`으로 켜뒀습니다.

### 고정 파라미터로 구간을 나눠 검증

워크포워드는 구간마다 파라미터를 **고릅니다.** 그런데 이 저장소의 권고는
고르지 말라는 것입니다(고르는 순간 무너진 사례가 셋). 그러면 재야 할 것은
"고정 규칙이 보지 않은 구간에서도 되는가"입니다.

```
4등분:  흑자 4/4   매수 후 보유 초과 1/4
6등분:  흑자 6/6   매수 후 보유 초과 3/6
8등분:  흑자 7/8   매수 후 보유 초과 4/8
```

**18개 구간 중 17개가 흑자이고, MDD가 전 구간에서 2.6~5.1%입니다.**
다만 매수 후 보유를 이기는 건 절반 이하입니다.

| 장세 | 전략 | 매수 후 보유 |
|---|---|---|
| 2020-03~2021-03 (불장) | +11.43% | **+577.29%** |
| 2018-01~2019-01 (폭락) | −2.17% | **−74.00%** |
| 2022-04~2023-05 (약세) | +4.24% | −28.20% |
| 2025-07~2026-08 (횡보) | +0.03% | −33.60% |

**이건 "시장을 이기는 전략"이 아닙니다. "낙폭을 피하면서 조금씩 버는 전략"입니다.**
연 3.8%에 MDD 6%. 매수 후 보유는 연 23%에 MDD 81%입니다.
리스크 대비로는 비슷하고(6.3 vs 6.1) **경로가 완전히 다릅니다.**

파라미터를 탐색하는 워크포워드에서는 효율 **0.35**, 검증 흑자 3/4였습니다
(`ema_cross` 0.20, 4시간봉 돈치안 0.02보다 낫지만 여전히 성과의 65%가 사라집니다).
채널 40이 4구간 중 3구간에서 선택된 것은 고정값으로 쓰라는 권고를 뒷받침합니다.

### 페이퍼 트레이딩을 돌렸더니 버그가 셋 나왔습니다

페이퍼는 백테스트와 **다른 코드 경로**입니다. 백테스트는 `backtest/engine.py`의
단순 루프이고, 페이퍼는 실전과 똑같은 `TradingEngine`을 탑니다. 그래서
조용히 갈라질 수 있고, 실제로 갈라져 있었습니다.

```
백테스트              142건   자본 274.61
페이퍼 (버그 있을 때)    76건   자본 237.70
페이퍼 (고친 뒤)       142건   자본 274.04
```

**1. 리플레이가 벽시계를 썼습니다.** 8.6년치를 몇 초에 재생하는 동안
전체가 하루로 취급되어, 일일 손실 한도와 연속 손실이 한 번 걸리면 영영
안 풀렸습니다. 체결이 142건 → 76건으로 줄었습니다.

**2. 페이퍼가 펀딩비를 안 물렸습니다.** `cmd_paper`가 `funding_rate`를
거래소 객체에 안 넘기고 있었습니다. 최소 주문 수량도 마찬가지였습니다.
**페이퍼가 백테스트보다 4.8% 좋게 나왔습니다.**

**3. 리플레이가 이전 실행의 연속 손실을 물려받았습니다.** 저장된 매매일지에서
읽어오고 있어서, 두 번째 실행이 첫 실행에 오염됐습니다.

> **2번이 특히 위험합니다.** 페이퍼가 실제보다 좋게 나오면 그대로 실전에
> 갑니다. 실전 직전에 딱 속기 좋은 자리입니다.

고친 뒤 두 경로가 0.2% 안에서 일치합니다. 남은 차이는 마지막 미청산 포지션을
정리하는 방식(백테스트는 `close_position`, 리플레이는 `force_close`)이고,
데이터가 끝나는 지점의 인공물이지 체계적 차이가 아닙니다.

**두 경로가 다시 갈라지지 않도록 테스트로 묶었습니다**
(`test_paper_matches_backtest.py`). 체결 수는 정확히 일치해야 하고, 자본은
1% 안이어야 하며, **페이퍼가 백테스트보다 좋게 나오면 실패합니다** —
비용을 빠뜨렸을 때 정확히 그 방향으로 어긋나기 때문입니다.

```bash
# 저장된 캔들로 실전 코드 경로를 검증 (네트워크 불필요)
PYTHONPATH=src python3 -m dorothy.cli paper --config config/config.yaml     --csv data/btc_12h.csv --offline

# 실시간 (거래소 공개 시세, API 키 불필요)
PYTHONPATH=src python3 -m dorothy.cli paper --config config/config.yaml
```

실시간 페이퍼는 12시간봉이라 의미 있는 표본이 쌓이는 데 몇 달 걸립니다.

## 호가 데이터 수집기 — 지금부터 모아야 합니다

이 저장소의 모든 분석은 OHLC로 했습니다. 그런데 **"슬리피지가 나고 유동성이
다시 쌓인다"는 이야기는 OHLC로는 흉내만 낼 수 있습니다.** 봉 안에서 저가를
언제 찍었는지, 그 순간 어느 쪽이 공격했는지 알 수 없기 때문입니다.

체결 내역에는 그게 그대로 남습니다.

```
같은 밀리초에 여러 체결이 가격을 밟고 올라감
  → 시장가 주문이 호가를 뚫은 것. 그게 슬리피지입니다.
```

과거 호가 데이터는 **무료로 구할 수 없습니다**(용량이 커서 아무도 안 뿌립니다).
유료는 Tardis.dev·Kaiko 같은 곳이 파는데 1년치가 수백 GB에 비용도 상당합니다.
그래서 **지금부터 모으는 수밖에 없습니다.**

```bash
pip install -r requirements-collect.txt

# 1) 먼저 몇 초만 받아서 눈으로 확인하세요
PYTHONPATH=src python3 -m dorothy.cli collect --probe

# 2) 확인됐으면 계속 돌립니다 (Ctrl+C로 중단, 저장은 유지됩니다)
PYTHONPATH=src python3 -m dorothy.cli collect --db data/collect.db

# 체결만 모으면 용량이 1/100로 줄어듭니다
PYTHONPATH=src python3 -m dorothy.cli collect --no-book

# 현황
PYTHONPATH=src python3 -m dorothy.cli collect-status --db data/collect.db
```

**API 키가 필요 없습니다.** 공개 스트림이라 읽기만 합니다.

### 빠진 구간을 반드시 기록합니다

재접속하는 동안 놓친 구간을 모르면, 나중에 **"그 시각에 체결이 없었다"와
"우리가 못 받았다"를 구분할 수 없습니다.** 그 둘을 섞으면 결론이 조용히 틀립니다.

그래서 `gaps` 테이블에 세 가지를 기록합니다.

| 종류 | 언제 |
|---|---|
| `trade` | 체결 ID가 건너뛰었을 때 (몇 건 놓쳤는지까지) |
| `book` | 호가 갱신 ID가 끊겼을 때 (스냅샷 재동기화 필요) |
| `disconnect` | 연결이 끊겨 재접속하는 동안 |

> ⚠ **이 코드는 네트워크가 막힌 환경에서 작성됐습니다.**
> 파싱·저장·빠짐 감지는 32개 테스트로 전부 검증했지만,
> **실제 거래소 접속만은 확인하지 못했습니다.**
> 그래서 `--probe`를 먼저 돌려 눈으로 보시라고 만들어 뒀습니다.
> 통신 부분을 일부러 얇게 두어(붙고·받고·넘기고·재접속), 문제가 생겨도
> 어디를 고칠지 분명하게 했습니다.

### 얼마나 모아야 하나

체결만 모으면 BTC 하루에 대략 수십~수백 MB입니다. 호가까지면 그 100배쯤 됩니다.
**최소 몇 주**는 모여야 "슬리피지 → 유동성 유입 → 되찾기"를 통계로 볼 수
있습니다. 이 저장소에서 계속 확인한 대로, 30건짜리 표본으로는 아무것도
판정할 수 없습니다.

## 슬리피지 스윕-되찾기 — 재보고 접었습니다

호가창이 얇을 때 큰 주문이 들어오면 가격이 여러 호가를 뚫고 내려갑니다(슬리피지).
그 자리에 다시 유동성이 쌓이고 가격이 원래 자리 위로 돌아오면, 방금 그 하락이
진짜 매도세가 아니라 **유동성 부족**이었다는 해석이 가능합니다.

OHLC로 이렇게 번역했습니다 (`analysis/reclaim.py`).

| 현상 | OHLC 신호 |
|---|---|
| 슬리피지 | 긴 아래꼬리 (봉 길이의 50%↑, ATR의 0.5배↑) |
| 유동성 유입 | 거래량이 최근 50봉 평균의 1.5배↑ |
| 시작가 이상 재시작 | 종가가 시가 위 **그리고** 뚫었던 직전 저점 위 |

셋을 **동시에** 요구합니다. 꼬리만 보면 그냥 변동성이고, 거래량만 보면 방향이 없습니다.

### 결과 — 18개 조합 중 17개 마이너스

```
TF   조건              건수    승률   1회 순수익      t     손절률
1h   기본 롱           483   37.3%   -0.1495%   -1.93    62%
1h   완화 롱           734   32.6%   -0.2853%   -4.96    66%
1h   완화 숏           623   35.8%   -0.2018%   -4.01    62%
4h   엄격 롱            36   44.4%   +0.2431%   +0.50    50%  ← 유일한 양수
12h  기본 롱            24   33.3%   -1.1726%   -1.88    33%
```

유일한 양수는 18번 시도해서 나온 36건짜리 `t=0.50`입니다. 근거가 못 됩니다.

**주목할 것은 `t = −4.96`입니다.** 조건을 완화해 표본을 734건까지 늘리니
**믿을 만하게 지는** 쪽으로 수렴합니다. 우연이 아니라 실제로 나쁜 신호입니다.

손절률을 보면 이유가 보입니다. 1시간봉에서 **62~66%가 손절로 끝납니다.**
되찾은 것처럼 보인 뒤에도 가격이 계속 내려갑니다.

### "그럼 반대로 하면?"

안 됩니다.

```
완화 롱:  순수익 −0.2853%  =  수수료 전 −0.0653%  −  비용 0.22%
뒤집으면:  수수료 전 +0.0653%  −  비용 0.22%  =  −0.155%
```

**역신호의 크기(0.065%)가 수수료(0.22%)보다 작습니다.** 뒤집어도 수수료가 먹습니다.

> ⚠ **이 측정의 한계.** OHLC로는 봉 안의 순서를 모릅니다 — 저가를 언제 찍었는지,
> 거래량이 그 순간에 몰렸는지 알 수 없습니다. 진짜 슬리피지-유동성 패턴은
> **호가창 데이터**로 봐야 제대로 잡힙니다. 여기서 잰 것은 "그런 모양의 봉 다음에
> 무슨 일이 있었나"이지 인과가 아닙니다. 호가 데이터가 있으면 결과가 달라질 수
> 있습니다.

## 단타는 왜 어려운가 — 수수료 바닥선

전략을 고르기 전에 답해야 할 질문이 있습니다.
**이 타임프레임에서 수수료를 넘는 것이 애초에 산술적으로 가능한가?**

```bash
PYTHONPATH=src python3 -m dorothy.cli costfloor --csv data/btc_1h.csv
```

```
BTC 8.6년, 왕복 비용 0.220%

TF        봉수      봉당 움직임   수수료가 먹는 몫   손익분기 승률
1h     75,836        0.415%           53%          76.5%
2h     37,920        0.594%           37%          68.5%
4h     18,960        0.844%           26%          63.0%
6h     12,640        1.044%           21%          60.5%
8h      9,480        1.217%           18%          59.0%
12h     6,320        1.521%           14%          57.2%
1d      3,160        2.263%           10%          54.9%
3d      1,053        4.080%            5%          52.7%
```

**1시간봉에서 손익비 1:1로 매매하면 승률 76.5%를 넘어야 본전입니다.**
이 저장소에서 측정한 모든 전략의 승률은 **37~49%**였습니다. 근처에도 못 갑니다.

이유는 단순한 산수입니다.

| | 어떻게 변하는가 |
|---|---|
| **가격 움직임** | 시간의 **제곱근**에 비례 |
| **수수료** | 매매 횟수에 **선형** 비례 (0.22% 고정) |

실제 데이터가 정확히 그렇습니다. 1h 0.415% → 4h 0.844%로 **2.03배**인데
√4 = 2입니다. 측정한 지수는 **0.54** — 랜덤워크(0.50)에 거의 정확히 붙습니다.

> **우위는 √T로 늘고 비용은 T에 반비례해 쌓입니다.**
> 타임프레임을 반으로 줄이면 잡을 수 있는 움직임은 √2배만 줄어드는데
> 매매 횟수는 2배가 됩니다. 단타는 이 싸움을 가장 불리한 쪽에서 하는 것입니다.

이것이 이 저장소의 모든 실험이 짧은 타임프레임에서 더 나빴던 이유입니다.

```
ema_cross 롱전용   1h −53.20%   2h −19.31%   4h +18.43%
donchian          1h −84.89% (2,068거래)
```

전략이 나빠서가 아니라 **바닥선이 올라가서**입니다.

### 메이커로 바꾸면 — 산수로는 크게 내려갑니다

```
방식                          왕복       1h       4h       1d
시장가 (테이커)               0.220%    76.5%    63.0%    54.9%
진입만 지정가                 0.130%    65.7%    57.7%    52.9%
진입·익절 지정가 (승률 45%)    0.089%    60.8%    55.3%    52.0%
손절 포기 (메이커 전용)        0.040%    54.8%    52.4%    50.9%
```

1시간봉 손익분기가 **76.5% → 60.8%**로 내려갑니다. 가장 큰 지렛대입니다.

다만 두 줄에 단서가 붙습니다.

**"진입·익절 지정가"의 0.089%는 승률 45% 가정입니다.** 손절은 반드시
시장가로 나갑니다 — **지정가 손절은 존재할 수 없습니다.** 가격이 손절가를
그냥 지나가면 체결이 안 되고 손실만 계속 커집니다. 그래서 왕복 비용이
승률에 따라 달라집니다. 이긴 매매는 익절(메이커)로, 진 매매는 손절(테이커)로
끝나기 때문입니다. **승률이 낮을수록 이 값이 올라갑니다.**

**"손절 포기"가 가장 싸 보이지만 비용을 아낀 게 아닙니다.**
손실 한도를 포기한 것입니다. 한 번의 큰 역행이 계좌를 끝냅니다.
이 저장소가 손절 없는 진입을 **거부**하도록 설계된 이유가 그것입니다
(위 "안전장치" 참고).

그리고 이 표는 **지정가가 체결된다고 가정**합니다. 실제로는 진입도 놓치고
익절도 안 닿습니다. 그것까지 넣은 결과는 아래 "메이커 진입 검증"에 있습니다 —
거기서는 **놓친 신호가 잡은 신호보다 5배 좋았습니다.**

### 나머지 지렛대

- **수수료 등급을 올린다** — 거래량·보유량 할인
- **손익비를 키운다** — 익절을 손절의 2배로 잡으면 필요 승률은 내려가지만
  그만큼 승률 자체도 내려갑니다. 공짜가 아닙니다

## 레버리지가 답이 아닙니다 — 선물 거래에서 가장 실질적인 결과

`dorothy leverage`로 배율별 결과를 냈습니다. 변동성 드래그·펀딩비·청산을
전부 넣었습니다.

```
BTC 8.6년(2018~), 4시간봉, 1배까지 현물(펀딩 없음)

전략                배율      수익률      MDD   수익/MDD    펀딩
매수 후 보유       1.00x    +531.1%    77.1%     6.89     0.0%
```

|---|---|
| **변동성 드래그** | +50%와 −50%를 번갈아 맞으면 원금이 줄어든다. 배율의 **제곱**으로 커진다 |

### "낙폭을 줄였으니 레버리지로 되찾는다"는 틀렸습니다

제가 앞에서 그렇게 주장했는데, 재보니 성립하지 않습니다. 변동성 타게팅
1.25배(+579.9%, MDD 80.5%)와 그냥 1배 보유(+531.1%, MDD 77.1%)는
**수익 차이가 작은데 낙폭은 타게팅 쪽이 더 큽니다.**

> ⚠ **그리고 이 둘의 우열은 평가 시작점에 따라 뒤집힙니다.**
> 평가를 121봉부터 시작하면 타게팅 1.25배가 이기고(7.20 vs 6.89),
> 481봉부터 시작하면 1배 보유가 이깁니다(10.05 vs 8.99).
> 차이는 2018년 1~3월 폭락 구간을 포함하느냐입니다.
> **둘 중 하나를 고를 근거가 데이터에 없습니다.**

윈도우와 무관하게 **양쪽 실행에서 모두 성립한 것**만 적으면 이렇습니다.

- 배율 1.25배를 넘으면 어떤 경우에도 나빠진다
- 2배 이상은 재앙이다 (MDD 94~100%)
- 펀딩비가 배율에 비례해 자본을 갉아먹는다
- 1배 근처에서 매수 후 보유와 변동성 타게팅은 우열을 가릴 수 없다


## 방향을 맞히지 않는 쪽 — 변동성 타게팅

여기까지 시도한 것은 전부 **방향 예측**이었고 전부 매수 후 보유에 졌습니다.
그래서 방향을 아예 안 맞히는 쪽으로 옮겼습니다.

하는 일은 하나입니다.

```
수량 = 목표변동성 ÷ 최근 실현변동성
```

변동성이 커지면 줄이고 잠잠하면 늘립니다. **어느 방향으로 갈지는 전혀 모릅니다.**
이게 예측이 아닌 이유는, 수익률은 예측이 거의 안 되지만 **변동성은 뭉쳐서
나타나기 때문**입니다(volatility clustering). 어제 크게 움직였으면 오늘도 크게
움직일 확률이 높다 — 어느 쪽으로인지는 여전히 모릅니다. 그 비대칭만 씁니다.

```bash
PYTHONPATH=src python3 -m dorothy.cli voltarget --csv data/btc_4h.csv     --target-vol 0.5 --max-leverage 1.0 --band 0.3
```

### 벤치마크와 조건을 맞추는 것이 결론을 바꿨습니다

처음 돌렸을 때 타게팅이 크게 졌습니다(수익/MDD 4.62 → 0.88). 원인은 전략이
아니라 **비교 방식**이었습니다. 매수 후 보유는 현물이라 펀딩비를 안 내는데,
타게팅에는 전체 노출에 펀딩비를 물렸습니다. 8.6년치 펀딩비만 109.8%였습니다.

그래서 `venue` 구분을 넣었습니다.

| venue | 펀딩비를 무는 대상 |
|---|---|
| `spot` (기본) | 1배 초과분만. 1배까지는 현물로 들고 있다고 본다 |
| `perp` | 전체 노출. 무기한 선물로 만들면 1배도 펀딩을 낸다 |

**8.6년을 1배로 들고만 있어도 펀딩비가 100%를 넘습니다.** 현물 벤치마크와
선물 전략을 나란히 놓으면 전략이 부당하게 집니다. 이건 비교의 문제이지
전략의 문제가 아니었습니다.

### ⚠ 아래 검증에는 결함이 있었습니다 — 기준선이 행마다 달랐습니다

타임프레임을 다시 재다가 발견했습니다. 매수 후 보유 기준선이 설정마다
달랐습니다.

```
측정 구간 5일 고정   → 보유 기준선 +365 ~ +493%
측정 구간 20일 고정  → 보유 기준선 +530 ~ +584%
측정 구간 40일 고정  → 보유 기준선 +784 ~ +822%
```

**원인은 워밍업입니다.** `lookback`이 길면 그만큼 앞부분을 건너뛰고 평가를
시작하는데, 잘려 나간 2018년 초는 폭락 구간이었습니다. 시작 가격이 낮아지니
보유 수익률이 저절로 뛴 것입니다.

즉 **`lookback`을 바꾸면 비교 기간 자체가 바뀝니다.** 그러면 승률 비교가
성립하지 않습니다. 아래 격자 64칸을 전부 `hold = 4.62` 하나와 비교했는데,
그 4.62는 `lookback=30` 기준이었습니다. `lookback=120`인 칸은 실제로는
더 늦게, 더 유리한 구간에서 시작했습니다.

> **"lookback 120봉 16/16 승"이라는 결론을 철회합니다.** 그 단조 증가는
> 변동성 추정이 안정돼서가 아니라, 긴 lookback이 폭락 구간을 더 많이
> 건너뛰어서 생긴 것일 수 있습니다. 둘을 구분하지 못한 상태였습니다.

`analyse()`에 `start_index`를 넣어 모든 설정이 **같은 날짜 구간**을 평가하고
워밍업은 그 이전 데이터에서 가져오게 고쳤습니다. 테스트로 못 박아 뒀습니다
(`test_start_index_makes_baselines_comparable`).

아래는 결함이 있는 채로 남겨둡니다. 어떤 검증이 어떻게 새는지가
결론보다 쓸모 있습니다.

### (결함 있음) 검증 — 고른 것을 전부 훑었다고 생각했습니다

앞선 두 번의 실패가 "안쪽 파라미터만 검사했다"였으니, 이번엔 파라미터 격자
64개 + 타임프레임 6개 + 연도별 9년을 한꺼번에 봤습니다.

**격자 64개 중 43개(67%)가 매수 후 보유를 이깁니다.** 그런데 차원별로
쪼개면 하나가 지배적입니다.

```
lookback (변동성 측정 구간)        승률       중앙값
   15봉                       5/16  ( 31%)     4.13
   30봉                       9/16  ( 56%)     4.78   ← 처음 고른 값
   60봉                      13/16  ( 81%)     5.54
  120봉                      16/16  (100%)     6.21
```

**단조 증가이고, 120봉은 16개 전부 이깁니다.** 목표변동성과 밴드는 이만큼
뚜렷하지 않습니다(각각 50~75%, 56~75%).

그리고 이건 설명이 붙습니다. **측정 구간이 짧으면 변동성 추정치가 흔들리고,
그러면 필요 없는 재조정을 반복하며 수수료와 휩쏘를 먹습니다.** 길수록
추정이 안정됩니다. `lookback ≥ 60`만 보면 29/32(91%), 최소 4.47,
중앙값 5.91입니다.

**앞선 실패와 결정적으로 다른 점**: 그때는 제가 고른 값이 **꼭대기**였습니다.
이번엔 제가 고른 `lookback=30`이 56% 구간이고, 좋은 구간은 제가 **안 고른**
쪽입니다. 그리고 그 경계가 우연이 아니라 메커니즘으로 설명됩니다.

**두 검사 모두 같은 5년 창 안에서 돌았기 때문입니다.** 창 자체가 편향돼 있으면
그 안에서 아무리 갈라 봐도 편향이 드러나지 않습니다.

| 검사 | 잡아내는 것 | 못 잡는 것 |
|---|---|---|
| 파라미터 고원 | 파라미터 과최적화 | 기간·타임프레임 선택 |
| 연도별 분해 | 특정 해 의존 | 그 창에 없는 장세 |
| 워크포워드 | 학습·검증 누수 | 창 밖 장세 |
| **타임프레임 스윕** | **타임프레임 선택 편향** | 기간 선택 |
| **기간 확장** | **기간 선택 편향** | 그 자산 고유의 성질 |

**고른 것은 전부 검사해야 합니다.** `fast`/`slow`만 파라미터가 아니라
타임프레임도, 데이터 기간도, 방향을 끌지 말지도 전부 제가 고른 값입니다.
그중 하나라도 안 훑으면 그쪽으로 편향이 새어 들어옵니다.

**데이터를 늘리는 것이 다른 어떤 검증보다 강력했습니다.**
5년치로 세 검사를 통과시키는 것보다, 3.6년치를 더 붙이는 쪽이 답에 가까웠습니다.

아래 절은 삭제하지 않고 남겨둡니다. 무엇이 그럴듯해 보였는지, 그리고
그게 왜 부족했는지가 결론 자체보다 쓸모 있기 때문입니다.

### 하락장에서도 버티는가 — 이게 핵심 검증입니다

### "롱이 항상 낫다"가 아닙니다

같은 데이터를 방향별로 분해하면(`dorothy side`) 갈립니다.

```
전략               방향   건수    수수료 전    수수료 후      t      합계
donchian(40)        롱    379    +0.402%    +0.182%   0.95   +69.0%
donchian(40)        숏    295    +0.001%    -0.219%  -0.81   -64.5%
ema_cross           롱    100    +0.844%    +0.624%   1.62   +62.4%
ema_cross           숏    100    +0.096%    -0.124%  -0.33   -12.4%
supertrend          롱    129    -0.082%    -0.302%  -0.90   -39.0%

mean_reversion      숏    177    +0.227%    +0.007%   0.02    +1.2%  ← 숏이 낫다
```

| 전략 성격 | 우위 방향 |
|---|---|
| 추세추종 (돈치안, ema_cross) | **롱** |
| 평균회귀 (supertrend, mean_reversion) | **숏** |

오르는 자산에서는 돌파 롱이 통하고, 급등을 되받는 숏이 통합니다.
**방향 하나가 늘 옳은 게 아니라 전략 성격과 방향이 맞아야 합니다.**
그래서 `dorothy side`는 어느 쪽을 끄라고 정해주지 않고 양쪽을 나란히 보여줍니다.

### 파라미터 안정성 — 봉우리인가 고원인가

성과가 정확히 `20/50`에서만 나오면 잡음입니다. 주변에서도 유지돼야 진짜입니다.
25개 조합을 전부 돌렸습니다.

```
              40        50        60        80       100   ← slow
  10       -2.6%     -0.2%     -0.2%    +13.7%     +8.8%
  15       +2.5%    +12.5%     +8.6%     +6.5%     +7.2%
  20      +16.8%    +18.4%    +16.9%    +13.1%     +8.7%
  25      +19.8%    +22.4%    +14.2%     +8.1%     +7.1%
  30      +15.6%    +27.9%     +7.7%     +8.9%     +4.9%
↑ fast

조합 25개 중 흑자 22개 (88%)   중앙값 +8.8%   최대 MDD 10.6%
```

**뾰족한 봉우리가 아니라 넓은 고원입니다.** `fast ≥ 15` 구간은 20개 조합이
전부 흑자입니다. 약한 것은 `fast=10` 한 줄뿐이고, 너무 빨라 휩쏘에 당한다는
설명이 붙습니다.

그리고 가장 중요한 것: **기본값 20/50(+18.4%)은 최고가 아닙니다.**
최고는 30/50(+27.9%)입니다. 제가 봉우리를 고른 게 아니라 넓은 좋은 구간 안에
기본값이 들어가 있다는 뜻입니다.

> **그래서 30/50으로 바꾸지 않습니다.** 그게 정확히 돈치안을 무너뜨린 행동입니다
> (채널 20/40/60 중 최고를 골랐고 → 워크포워드 효율 0.02).
> 고원 안에 있다는 게 중요하지, 고원의 어느 지점인지는 중요하지 않습니다.
> 이 표를 보고 최고점으로 옮기고 싶어지는 충동이 바로 과최적화입니다.

### 그런데 아직 실전에 넣을 단계가 아닙니다

정직하게 남은 문제를 적습니다.

종합하면 이렇습니다.

| 검증 | 5년 창 결과 | 8.6년으로 늘린 뒤 |
|---|---|---|
| 파라미터 안정성 | ✅ 25개 중 22개 흑자 | (재검증 필요) |
| 장세 견고성 | ✅ 6년 중 5년 흑자 | ❌ 9년 중 5년, 2018 폭락장 −4.11% |
| 리스크 대비 | ✅ 3.03 vs 0.89 | ❌ 1.31 vs 5.98 |
| 통계적 유의성 | ❌ t=1.62 (2.0 필요) | ❌ 여전히 미달 |
| 워크포워드 | ⚠️ 효율 0.20, 검증 27거래 | ⚠️ 재검증 필요 |

**구조는 건전한데 표본이 얇습니다.** 앞의 셋이 통과했다는 건 우연히 맞은
곡선이 아니라는 뜻이고, 뒤의 둘이 걸린다는 건 아직 "확실하다"고 말할 수
없다는 뜻입니다. 남은 문제를 구체적으로 적으면:

- **t = 1.62.** 100거래로는 우연과 구별되지 않습니다. |t| ≥ 2가 필요합니다
- **워크포워드 효율 0.20.** 학습 성과의 80%가 검증에서 사라집니다.
  돈치안(0.02)보다 10배 낫고 흑자 구간도 3/4이지만, 검증 거래가 27건뿐입니다
- **파라미터를 탐색하면 무너집니다.** 워크포워드가 구간마다 다른 최적값을 고릅니다.
  `fast=20 slow=50` **기본값을 그대로 쓰는 것**이 이 결과의 전제입니다

마지막 항목이 중요합니다. 돈치안40은 제가 20/40/60 중에 **골랐고**, 그래서
워크포워드에서 무너졌습니다. `ema_cross`는 파라미터를 하나도 안 건드렸고
바꾼 것은 `allow_short: false` 하나뿐입니다. 고른 게 없으니 과최적화될 여지도
그만큼 적습니다.

설정은 `config/ema_long.rejected.yaml`에 남겨뒀습니다 — **추천이 아니라
왜 추천이 아닌지의 기록입니다.** 파일 첫머리에 뒤집힌 경위를 적어뒀습니다.

```bash
# 직접 재현해 보려면 (실전용이 아닙니다)
PYTHONPATH=src python3 -m dorothy.cli backtest --config config/ema_long.rejected.yaml --csv data/btc_4h.csv
PYTHONPATH=src python3 -m dorothy.cli side     --config config/ema_long.rejected.yaml --csv data/btc_4h.csv
```

- `available(include_retired=False)`에서 빠집니다
- 고를 때마다 사유와 함께 경고가 뜹니다
- 폐기 사유에는 **반드시 거래 수와 수익률이 들어갑니다** (테스트로 강제합니다).
  "별로였다"는 폐기 사유가 아닙니다

| ~~`ict_confluence`~~ | **폐기됨** (아래 참고) |
| `funding_bias` | 0거래 — 한 번도 신호가 안 났습니다. 증거 자체가 없습니다 |

> 이 표도 처음엔 `funding_bias`를 "무작위 대비 우위"로 올려놨습니다. 0거래인데도요.
> 이긴 게 아니라 **참가하지 않은** 겁니다. 지금은 0거래 전략을 따로 떼어
> "신호가 한 번도 나오지 않았습니다"라고 말하고, 승패 판정에서 제외합니다.
| `mtf_filter` `regime_filter` `session_filter` | 아래 참고 |

### 표가 거짓말을 하고 있었습니다

`session_filter`와 `donchian`을 보세요. **2,068거래 -84.89%로 완전히 같습니다.**

그리고 이 셋은 폐기 표시하지 않았습니다 — 필터가 진 게 아니라 켜진 적이 없으니까요.

## AI 트레이딩이 실제로 쓰는 방식 — 그리고 우리가 재본 결과

"AI로 가격을 예측한다"는 건 실무에서 거의 안 합니다. 실제로 쓰이는 건 넷입니다.

| 방식 | 하는 일 | 왜 쓰나 |
|---|---|---|
| **메타라벨링** | 기존 전략이 **방향**을 정하고, 모델은 **취할지 말지**만 결정 | 방향 예측은 정확도 상한이 52~55%. 취사 선택은 훨씬 쉬운 문제 |
| **국면 분류** | 지금이 추세장인지 횡보장인지 분류해 전략을 갈아끼움 | 하나의 전략이 모든 장에서 통하지 않는다는 사실의 반영 |
| **집행 최적화** | 진입/청산을 언제·어떻게 쪼갤지 | **가장 확실하게 돈이 되는 영역**. 예측이 아니라 비용 절감이라 검증이 쉽다 |
| **강화학습** | 포지션 크기·보유 시간을 직접 학습 | 논문은 많지만 실전 성공 사례는 드물다. 과최적화가 극심 |

이 중 **메타라벨링**을 구현했습니다(`dorothy metalabel`). 가장 실용적이고,
기존 전략을 버리지 않고 개선하는 방식이라서입니다.

### 그리고 실제 데이터에서 실패했습니다

BTC 1시간봉 5년(43,825봉), 1차 전략은 돈치안 40. 표본 2,535건.
purging·embargo를 적용한 5구간 워크포워드 검증 결과입니다.

```
  구간     학습     검증    기본승률    필터후    취함      개선
     0    412    422     42.2%    39.2%    125   -3.0%p
     1    844    422     40.5%    42.9%     77   +2.3%p
     2   1264    422     42.9%    40.7%     27   -2.2%p
     3   1684    422     42.9%    44.7%     47   +1.8%p
     4   2108    422     40.3%    54.5%     33  +14.3%p
  평균 개선  +2.7%p
```

승률만 보면 성공입니다. **여기서 멈추면 안 됩니다.** 돈으로 보면 이렇습니다.

```
  왕복 비용 0.220%  ← 1회 기대수익이 이걸 넘어야 번다

  구분          건수   1회(수수료 전)  1회(수수료 후)
  필터 없음     2110       +0.028%       -0.192%  ✗
  임계 0.50      469       +0.118%       -0.102%  ✗
  임계 0.55      309       +0.059%       -0.161%  ✗
  임계 0.60      186       +0.025%       -0.195%  ✗
  임계 0.65      115       -0.225%       -0.445%  ✗
  임계 0.70       72       -0.307%       -0.527%  ✗
```

세 가지가 한 번에 보입니다.

**1. 돈치안 40의 수수료 전 우위는 +0.028%/회 — 사실상 0입니다.**
5년, 2,110거래를 해서 수수료 전 총수익이 +0.6%였습니다. 동전 던지기입니다.
그동안 낸 수수료가 2,110 × 0.22% = **464%**. 손실 전액이 수수료입니다.

**2. 그래서 필터로는 못 고칩니다.** 비용을 넘으려면 모델이 우위를 **7.8배**로
키워야 하는데, 필터가 할 수 있는 일이 아닙니다. 필터는 있는 우위를 골라낼 뿐,
없는 우위를 만들지 못합니다.

**3. 임계값을 올릴수록 나빠집니다.** 0.50에서 +0.118%였다가 0.70에서 -0.307%.
모델이 "확신"할수록 성적이 나쁘다는 건, 그 확신이 실제 우위와 **무관**하다는 뜻입니다.
잡음을 배운 겁니다. 검증 구간별 개선폭이 -3.0 / +2.3 / -2.2 / +1.8 / +14.3으로
들쭉날쭉한 것도 같은 신호입니다 — 마지막 구간 하나가 평균을 혼자 끌어올렸습니다.

`metalabel`은 이 판정을 자동으로 냅니다. 승률이 올라도 수수료를 못 넘으면 ✗라고 합니다.

```bash
pip install -r requirements-ml.txt      # numpy, scikit-learn (선택 의존성)
PYTHONPATH=src python3 -m dorothy.cli metalabel --csv data/btc_1h.csv --folds 5
```

### 4시간봉으로 옮기면? — 거의 살아났지만, 아직 아닙니다

위의 3번("거래 빈도를 줄인다")을 실제로 재봤습니다. 같은 5년 데이터를 4시간봉으로
리샘플(10,956봉)하고, 채널을 10으로 줄여 **실시간 기준 같은 길이**(40시간)를 봤습니다.

```
  구분           건수   수수료 전   수수료 후       t
  필터 없음      1230    -0.003%    -0.223%   -2.18  ✗
  임계 0.50       363    +0.458%    +0.238%    1.29  ?
  임계 0.55       252    +0.346%    +0.126%    0.58  ?
  임계 0.60       168    +0.171%    -0.049%   -0.18  ✗
```

1시간봉에서는 어떤 임계값도 비용을 못 넘었는데, 여기서는 **넘습니다**. 필터의
수수료 전 우위가 +0.458%/회 — 1시간봉(+0.118%)의 4배입니다.

**그런데 t=1.29입니다.** 1회 수익의 표준편차가 3.5%인데 평균이 +0.238%면,
363건으로는 부호조차 확신할 수 없습니다. 시드를 7개 돌려봤습니다.

```
 seed    임계 0.50 (수수료 후)
    1        +0.098%
    7        -0.096%
   42        +0.238%   ← 처음 돌린 값. 7개 중 제일 운 좋은 시드였습니다
   99        -0.037%
  123        +0.010%
 2024        +0.061%
31337        +0.106%
        평균 +0.054%   범위 -0.096 ~ +0.238
```

**흔들림(±0.17%p)이 평균(+0.054%)의 3배입니다.** 처음 본 +0.238%는 실력이 아니라
시드 운이었습니다. 한 번만 돌리고 "성공"이라고 했으면 그대로 속았을 겁니다.

다만 **수수료 전 우위는 21개 셀 전부 양수**였습니다(+0.124 ~ +0.458%, 평균 +0.27%).
방향은 맞고, 크기가 비용 앞에서 모자란 겁니다. 그래서 남은 지렛대가 비용입니다.

| | 왕복 비용 | 임계 0.50 순수익/회 |
|---|---|---|
| 테이커 (시장가) | 0.22% | **+0.054%** — 우연과 구별 불가 |
| 메이커 (지정가) | 0.14% | **+0.134%** — 의미 있는 크기 |

> ⚠ 다만 돌파 전략을 지정가로 넣으면 **못 먹는 체결이 하필 크게 간 것들**입니다.
> 메이커 전환은 공짜가 아니라 미체결 위험과의 교환입니다. 별도로 검증해야 합니다.

### 메이커 진입을 미체결까지 반영해서 재봤습니다

"지정가로 넣으면 왕복 0.22% → 0.13%"는 수수료만 본 얘기입니다. 지정가는 **가격이
되돌아와야** 체결되는데, 돌파 전략에서 안 돌아온 캔들은 대개 그대로 크게 간 캔들입니다.
즉 지정가는 비용을 깎는 대신 **좋은 매매를 골라서 놓칠 수 있습니다.**

`dorothy metalabel --maker`가 이걸 잽니다. 실제로 놓친 신호가 잡은 신호보다 좋았습니다.

```
지정가 = 종가 - 0.25 ATR, 대기 3봉

구분                     건수   수수료 전    비용   수수료 후       t      합계
시장가 — 전량 진입        252     +0.346%   0.22%     +0.126%    0.58    +31.7%
시장가 — 체결분만         202     -0.003%   0.22%     -0.223%   -0.93    -45.1%
지정가 — 체결분           202     +0.326%   0.13%     +0.196%    0.82    +39.6%
놓친 신호 (시장가 기준)     50     +1.755%       —           —       —
```

놓친 50건이 평균 **+1.755%** — 잡은 것(+0.326%)의 5배입니다. 예상대로 안 돌아온 캔들이
크게 간 캔들이었습니다. 그런데도 총액은 +31.7% → +39.6%로 늘었습니다. 체결된 202건을
**0.25 ATR 싸게** 잡은 이득이 더 컸기 때문입니다.

**그래서 오프셋을 쓸어봤습니다.** 이게 결론을 뒤집었습니다.

```
오프셋   대기   체결률   놓친것 수전   시장가 합계   지정가 합계     차이
  0.00     3    99.6%     +4.496%       +12.8%       +32.4%   +19.6%p
  0.10     1    88.2%     +1.129%       +12.8%       +34.5%   +21.7%p
  0.25     3    81.2%     +1.876%       +12.8%       +19.2%    +6.4%p
  0.50     3    64.4%     +1.683%       +12.8%        -1.9%   -14.7%p
  0.75     3    49.0%     +1.402%       +12.8%       -11.4%   -24.2%p
  1.00     1    11.5%     +0.501%       +12.8%        -8.2%   -21.0%p
```

**멀리 걸수록 단조롭게 나빠집니다.** 그리고 가장 좋은 건 오프셋 **0** — 즉
"더 싸게 사려 하지 않고 종가에 그냥 거는 것"입니다.

오프셋 0의 이득이 +19.6%p인데, 수수료 절감분이 0.09%p × 251건 = **+22.6%p**입니다.
거의 정확히 일치합니다. 즉 **이득의 전부가 수수료 절감이고, 가격 개선분은 0입니다.**
지정가로 더 싸게 사려는 시도는 놓친 매매값을 못 냅니다.

> ⚠ **오프셋 0의 체결률 99.6%는 시뮬레이션이 낙관적이라는 신호입니다.**
> "저가가 종가를 스쳤다"는 이유로 거의 다 체결 처리되는데, 실제로는 **호가 대기열**이
> 있습니다. 가격이 스치기만 하고 내 주문까지 안 내려오거나, 급하게 쓸려나가면
> 체결되지 않습니다. 이 모델은 대기열을 모사하지 않습니다.
> 보고서도 이 조건에서 경고를 냅니다.

**정리하면:**

| 시도 | 결과 |
|---|---|
| 지정가로 수수료 깎기 | ✅ 유효 — 왕복 0.22% → 0.13%, 5년 +22%p |
| 지정가로 더 싸게 사기 | ❌ 역효과 — 오프셋 클수록 단조 악화 |
| 그래서 전략이 살아났나 | ❌ **아니오** — 최선의 조건에서도 t=0.66 |

t가 여전히 1을 못 넘습니다. 비용을 깎아도 **우위 자체가 우연과 구별되지 않습니다.**
비용은 문제의 일부였을 뿐, 전부가 아니었습니다.

### 도구가 스스로를 속지 않게 만든 부분

처음 버전은 `임계 0.50 +0.238% ✓ 합격`이라고 했습니다. **틀린 판정이었습니다.**
평균만 보고 흔들림을 안 봤기 때문입니다. 지금은 이렇게 고쳤습니다.

- **t 통계량을 함께 낸다.** `|t| ≥ 2`가 아니면 ✓를 주지 않고 `?`로 표시합니다
- **합격 판정이 나와도 경고를 숨기지 않는다.** 임계값을 올릴수록 나빠지면(위 표가
  정확히 그렇습니다) 합격이든 아니든 말합니다 — 이전 버전은 ✓ 경로에서 조기 반환하며
  이 경고를 삼켰습니다
- **1차 전략이 수수료 전에도 음수면** "몇 배로 키우면 된다"고 하지 않습니다.
  필터로 고칠 문제가 아니라고 말합니다
- **1회 평균이 아니라 총액으로 판정합니다.** 지정가는 매매 수 자체를 줄이므로
  평균이 올라도 총액은 내려갈 수 있습니다. 실제로 처음엔 평균만 보고
  "지정가가 낫다"는 반대 결론이 나왔습니다
- **체결률이 비현실적으로 높으면 경고합니다.** 대기열을 모사하지 않는다는 사실을
  결과에 적어둡니다

### 여기서 배울 것

**수수료가 바닥선입니다.** 왕복 0.22%(테이커 0.06% × 2 + 슬리피지 0.05% × 2)면,
1회 기대수익이 0.22%를 넘는 전략만 살아남습니다. 1시간봉에서 이건 아주 높은 기준입니다.

그래서 순서가 이렇습니다.

1. **수수료 전 우위부터 만든다.** 모델도, 필터도, 파라미터 튜닝도 그 다음입니다.
   `metalabel`의 "필터 없음" 줄이 음수면 그 전략은 거기서 끝입니다.
2. **거래 빈도를 줄인다.** 우위가 0.1%/회라면 왕복 0.22%를 못 넘습니다.
   4시간봉으로 옮겼더니 필터의 수수료 전 우위가 +0.118% → +0.458%로 4배가 됐습니다
   (위 참고). 방향은 확실히 맞습니다. 다만 그것만으로는 아직 부족했습니다.
3. **메이커로 넣는다 — 단, 더 싸게 사려 하지 말고.** 왕복 0.22% → 0.13%는 실측으로도
   유효했습니다(5년 +22%p). 하지만 지정가를 종가보다 아래에 거는 순간 손해로 돌아섭니다
   (위 오프셋 표). 수수료만 가져가고 가격은 욕심내지 마세요.

4. **한 번 돌린 결과를 믿지 않는다.** `--seed`를 최소 5개는 바꿔 돌리세요.
   위에서 처음 본 +0.238%는 7개 시드 중 가장 운 좋은 값이었고, 평균은 +0.054%였습니다.

> ⚠ **모델을 쓴다고 검증이 쉬워지지 않습니다. 훨씬 어려워집니다.**
> 삼중 배리어 라벨은 진입부터 청산까지 여러 봉에 걸칩니다. 학습 표본의 라벨 구간이
> 검증 구간과 겹치면 모델은 검증 구간 가격을 이미 본 셈입니다. `purged_walk_forward()`가
> 이걸 잘라내고(purging), 검증 구간 직전 표본도 버립니다(embargo).
> 이거 없이 나온 "승률 70%"는 전부 누수입니다.

### 구성

```
src/dorothy/ml/
├── features.py     11개 특징 — 전부 인과적(미래 참조 없음), 전부 정규화됨
├── labeling.py     삼중 배리어 — 목표·손절·시간 중 먼저 닿는 것으로 라벨
├── validation.py   purged walk-forward + embargo
└── meta.py         학습 · 검증 · 손익 판정

src/dorothy/execution/maker.py       지정가 체결 시뮬레이션
src/dorothy/backtest/maker_report.py 시장가 vs 지정가 비교 (미체결 포함)
```

특징을 11개로 제한한 이유: 금융 데이터는 신호 대 잡음이 극도로 낮아서,
50개를 주면 모델은 잡음 50개를 외웁니다.
