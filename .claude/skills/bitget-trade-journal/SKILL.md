# 비트겟 → 노션 매매일지 자동 입력

레오(Siwoo)의 선물/레버리지 매매일지를 노션에 자동으로 기록하는 스킬.

## 이 스킬의 목적은 '기록'이 아니라 '분석 가능한 기록'이다

기록만 쌓이고 분석이 안 되면 의미가 없다. 실제로 초기 21건을 분석해보니
**손절액이 21건 전부 비어 있었고, 진입 근거는 2건에만 있었다.**
그래서 "어떤 셋업이 통하는가", "계좌 크기와 무관한 실력(R)은 얼마인가"를
물어볼 수 없었다.

따라서 아래 두 칸은 **비워둔 채로 페이지를 만들지 않는다**:

| 칸 | 없으면 못 하는 것 |
|---|---|
| **손절액** | R 분석 (손익 ÷ 손절액). 계좌 크기와 무관하게 매매를 비교하는 유일한 단위 |
| **진입 근거** | 셋업별 기대값. 어떤 진입이 통하고 어떤 게 안 통하는지 분류 |

"모르면 비워둔다"가 아니라 **"없었으면 없었다고 기록한다"**가 원칙이다.
빈칸은 정보가 없는 것이고, "손절 미설정"은 그 자체로 중요한 정보다.

## 대상 노션 데이터베이스

- 워크스페이스: Siwoo's Notion
- 데이터베이스: **매매 기록**
- data_source_id: `2e19bad3-6ac4-454f-a142-bcea1866535d`
- 상위 페이지: 📈 매매일지 (선물/레버리지)

노션 커넥터(`mcp__Notion__*`)가 연결되어 있어야 한다. 안 되어 있으면 연결을 안내한다.

## 순서

### 1. 입력 읽기

사용자가 붙여넣은 비트겟 공유 스크린샷(이미지) 또는 링크/텍스트를 읽는다.
이미지면 화면에서 값을 직접 읽어낸다.

### 2. 화면에서 뽑을 수 있는 값 추출

- 심볼 (예: BTCUSDT) → `심볼` (목록에 없으면 "기타" 또는 새 옵션)
- 방향 (Long/Short) → `방향` = "롱" 또는 "숏"
- 레버리지 (예: 10x) → `레버리지` (숫자만)
- 진입가 (Entry Price / Avg. Entry) → `진입가`
- 청산가 (Exit / Close / Mark Price) → `청산가`
- 실현 손익 (Realized PnL, USDT 금액) → `손익`
- ROI/수익률은 참고만 (수익률은 노션에서 자동 계산됨)

### 3. 부족한 값을 한 번에 묻는다 ← 이 단계가 핵심

비트겟 공유 화면에는 보통 **시작금액(증거금)**, **손절액**, **진입 근거**가 없다.
이 셋을 **한 메시지에** 묻는다. 질문을 나눠 던지지 말 것 — 귀찮아지면 건너뛰게 된다.

물을 때는 **선택지를 함께 제시**한다. 자유 서술을 요구하면 답이 안 온다.

> 스크린샷에서 못 읽은 값만 확인할게요.
>
> 1. **증거금(시작금액)**: 얼마 넣으셨나요?
> 2. **손절액**: 이 매매에서 잃어도 된다고 계획한 금액은?
>    (미리 정하지 않았으면 "없음"이라고 답해주세요)
> 3. **진입 근거**: 아래 중 가까운 것 하나 + 한 줄 설명
>    - `지지저항` 지지/저항 반응
>    - `되돌림` 추세 중 되돌림
>    - `돌파` 박스/채널 돌파
>    - `유동성스윕` 고점·저점 쓸고 반전
>    - `이평` 이동평균 크로스
>    - `뉴스` 뉴스/이벤트
>    - `감` 특별한 근거 없음

**AskUserQuestion 도구를 쓸 수 있으면 그걸로 물어라.** 선택지를 눌러 답하는 편이
타이핑보다 응답률이 훨씬 높다. 진입 근거는 선택지로, 금액 두 개는 자유 입력으로 받는다.

### 4. 답을 규칙대로 기록한다

**손절액**
- 금액을 답했으면 → `손절액` = 그 숫자
- "없음/안 정했음"이라고 답했으면 → `손절액` = `0` 으로 기록하고,
  `실수 태그`에 **"손절 미설정"**을 추가한다.
  (이 옵션이 노션에 없으면 새 옵션으로 만든다)
- **답을 안 받은 채로 페이지를 만들지 않는다.** 한 번 더 묻는다.

**진입 근거**
- 반드시 **`[셋업이름] 설명`** 형식으로 저장한다. 예:
  - `[유동성스윕] 전일 저가 쓸고 되돌아온 자리에서 롱`
  - `[되돌림] 상승 추세 중 0.618 되돌림 지지`
  - `[감] 근거 없이 진입`
- 대괄호 셋업 이름이 있어야 **분석 도구가 셋업별로 묶어서 기대값을 낼 수 있다.**
  자유 서술만 있으면 그룹화가 안 된다. 이 형식은 생략하지 않는다.
- 사용자가 셋업만 고르고 설명을 생략하면 `[셋업이름]`만 저장해도 된다.

**시작금액**
- 손익 금액이 화면에 없고 ROI(%)와 증거금만 있으면 `손익 = 증거금 × ROI%` 로 계산한다.

### 5. 결과 판정

손익 > 0 이면 `결과` = "익절", 손익 < 0 이면 "손절", 0에 가까우면 "본절".

### 6. 손절이 지켜졌는지 확인한다

`손절액`이 0보다 크고 손실이 났는데 **실제 손실이 손절액의 1.1배를 넘으면**,
계획한 손절이 지켜지지 않은 것이다. `실수 태그`에 "손절 늦음"을 추가하고
사용자에게 짧게 알린다.

> 계획 손절은 20달러였는데 실제로는 37달러 잃으셨네요. '손절 늦음' 태그를 달았습니다.

### 7. 페이지 생성

`mcp__Notion__notion-create-pages` 로 위 data_source_id 아래에 페이지를 만든다.

- 날짜는 **반드시 확장 키**로 넣는다: `"date:날짜:start": "YYYY-MM-DD"`
  (그냥 `"날짜"` 로 넣으면 오류남)
- `제목` 예: "BTCUSDT 롱 — 7/22" 처럼 심볼+방향+날짜로 짓는다.
- 스크린샷 이미지가 있으면 첨부(가능하면 `스크린샷` 파일 속성)하거나 페이지 본문에 남긴다.
- 페이지 본문(content)에는 반성일지 골격을 넣는다:
  `## 📍 진입 상황` / `## ✅ 잘한 점` / `## ⚠️ 실수·반성` / `## 🔧 다음 개선점`

### 8. 반성 유도

기록 후 "이번 매매에서 잘한 점 / 실수 한 가지씩 적어볼까요?" 라고 짧게 물어,
답을 받으면 `반성일지` 속성과 본문에 채운다.

### 9. 확인

만든 노션 페이지 URL과 자동 계산된 수익률(%)을 사용자에게 알려준다.

### 10. 10건마다 분석 제안

`회차`가 10의 배수가 되면 한 줄로 제안한다.

> 이번이 30회차네요. 노션에서 CSV로 내보내면
> `python -m dorothy journal <파일>` 로 셋업별 기대값과 R 분석을 볼 수 있습니다.

## 속성 매핑 요약

| 노션 속성 | 타입 | 비고 |
|---|---|---|
| 제목 | title | 심볼+방향+날짜 |
| 날짜 | date | `date:날짜:start` 확장 키 사용 |
| 심볼 | select | BTCUSDT/ETHUSDT/SOLUSDT/XRPUSDT/기타 |
| 방향 | select | 롱 / 숏 |
| 레버리지 | number | 배율 숫자 |
| 진입가 / 청산가 | number | |
| **진입 근거** | text | **필수. `[셋업이름] 설명` 형식** |
| 시작금액 | number($) | 증거금, 사용자에게 확인 |
| 손익 | number($) | 실현 손익 |
| **손절액** | number($) | **필수. 미설정이면 0 + "손절 미설정" 태그** |
| 수익률(%) | formula | 자동: 손익÷시작금액×100 (입력하지 말 것) |
| 결과 | select | 익절/손절/본절 (손익 부호로 판정) |
| 실수 태그 | multi_select | 계획대로/뇌동매매/추격매수/손절 늦음/과도한 레버리지/분할 실패/FOMO/익절 조급/손절 미설정 |
| 반성일지 | text | 복기 메모 |
| 스크린샷 | file | 비트겟 공유 이미지 |

## 셋업 이름 목록

진입 근거의 대괄호 안에는 아래 중 하나를 쓴다. 새로 만들지 말고 재사용해야
셋업별 통계가 쌓인다. 정말 맞는 게 없을 때만 새 이름을 만들고,
만들었으면 사용자에게 알려 다음부터 같은 이름을 쓰게 한다.

| 이름 | 뜻 |
|---|---|
| `지지저항` | 수평 지지/저항선 반응 |
| `되돌림` | 추세 중 되돌림(피보나치 포함) 진입 |
| `돌파` | 박스·채널·전고점 돌파 |
| `유동성스윕` | 고점/저점을 쓸고 되돌아온 자리 |
| `이평` | 이동평균 크로스/지지 |
| `뉴스` | 뉴스·이벤트 반응 |
| `감` | 특별한 근거 없음 (정직하게 이걸 고르는 것도 데이터다) |

## 주의

- `수익률(%)`, `회차`는 자동 계산/자동 증가라 값을 직접 넣지 않는다.
- 화면에서 확실하지 않은 숫자는 추측하지 말고 사용자에게 확인한다.
- **손절액과 진입 근거를 받지 못한 상태로 페이지를 만들지 않는다.**
  사용자가 두 번 이상 명확히 거부하면 그때는 진행하되,
  손절액은 0 + "손절 미설정" 태그로, 진입 근거는 `[감]`으로 남긴다.
  빈칸으로 두는 것만은 피한다 — 빈칸은 나중에 복구할 수 없다.
